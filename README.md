# kouhe3/skills

三个 Agent Skill，都只做一件事：**让 agent 先问再答，动手前先把「不知道」写下来。**

```bash
npx skills add kouhe3/skills
```

手动装：把 `skills/<name>/` 复制进 agent 的 skills 目录（`~/.claude/skills/`、`.agents/skills/`、`~/.omp/agent/skills/`）。

| Skill | 你什么时候需要它 |
| --- | --- |
| `helping` | 你向 agent 求助，它总是直接给方案 |
| `face-spaghetti` | 对着遗留代码或反编译产物开工，写完不知道对不对 |
| `talk-audit` | 你想让人压力测试一个想法，而不是听「好主意」 |

下面是它们各自改变的那一步（示例为示意，不是真实记录）。

术语：**停点** = 这一轮靠什么信号判断该停；**判据** = 跑一次就能得出是/否的检查；**台账** = 记「待证 + 怎么证伪 + 判据」的清单；**claim** = 一句能被证伪的断言，**承重 claim** = 它塌了整个想法就跟着塌。

## `helping`

> 用户：「我不知道还该不该继续待在这个项目里。」

**Before**
```
AI：可以从三个角度看：1) 职业发展 2) 团队氛围 3) 你的兴趣和长期目标。
建议各打一分，再按权重排序。希望对你有帮助。
```

**After**（第 1 轮只做一件事）
```
AI：在我给建议之前想先确认：你现在最需要的是有人听你说、一起想，
还是一个具体方案？
```

> 用户：「想理清楚。」第 2 轮仍然是问讯，不给方案：
```
AI：能给我一个具体例子吗——最近哪件事让你开始这么想的？
```

差别在**停点**：Before 一轮就结束，After 每轮停在一个可观察的信号上。

## `face-spaghetti`

> 用户：「这是从 exe 反编译出来的，帮我把这个函数补完。」

**Before**
```
AI：我先看看入口在哪……（打开 IDA，开始改代码）
三小时后：判据写不出来，改动的对错无法验证。
```

**After**
```
AI：形态判定：反编译产物 → 来源不可信，走闸门。
判定：改造后做（关键前提未证——这个函数是否真的被调用）。
第一个动作不是改代码，是台账落一行：
  待证 | 假设：该函数由 0x401000 的调用点进入
       | 互斥预测：若为死代码，则交叉引用数为 0
       | 判据：xref = 0 → 判死代码，进垃圾桶
先跑这个探针，再谈实现。
```

差别在**第一条动作是记录而不是编辑**：不知道留在脑子里，就永远无法判断改对没改对。

## `talk-audit`

> 用户：「我想把整个站点换成静态生成器，你觉得呢？」

**Before**
```
AI：好主意！静态站更快、更省、更安全。建议先用 Astro 试一版，
我可以直接帮你搭起来。
```

**After**
```
AI：先拆 claim，标出承重的那条：
C1 静态生成更快      —— 事实，可测
C2 现有用户不需要发帖 —— 假设（承重）
C3 迁移成本低于维护成本 —— 事实，但要算
承重的是 C2，而它是假设。你要对这条做什么：赞同 / 质疑 / 重构 / 标未知？
```

> 用户：「质疑。」
```
AI：那先定一个廉价测试：统计近 90 天有发帖行为的用户占比。
低于 5%，才轮得到谈 C2 成立。
```

差别在**建议被挂在哪条 claim 上**：没有可证伪的接口，「好主意」就只是让人选择信或不信。

---
