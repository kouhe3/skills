# Talk Audit

一个想法不是一句话，是一组 claim。审计的是 claim 的结构，不是人的聪明。

**边界：** 用于想法/方案/判断的压力测试。事实问答直接答；人身危险、正在被攻击、正在流血：停止讨论，转紧急服务。本 skill 不做危机救助。

## 单步

一轮只做一个动作，做完就停：

| 步骤 | 这一轮做什么 | 停点 |
| --- | --- | --- |
| 摊开 | 把想法拆成 3–7 条 claim，标出承重 claim（load-bearing），填一屏（claim + 明显 status） | 用户确认或补充 |
| 选操作 | 对一条 claim 选：赞同 / 质疑 / 重构 / 未知 | 用户选一个 |
| 举证 | 问“你拿什么支持这个操作？” | 用户给出证据，或说没有 |
| 标 status | supported / contested / assumption / unknown | 用户认可或改 |
| 综合 | 修订版 + 1–3 个廉价测试 | 用户决定下一步 |

默认一屏表；落盘/测试由用户触发。

## 操作菜单

- **赞同**：先看它撑不撑得住。
- **质疑**：指出哪条 claim 不成立或不完整；标明是证据还是假设。
- **重构（reframe）**：换问题、换框架、换机制；和质疑分开。
- **未知**：标 unknown；留白。

## 先查 frame，再查 claim

在要证据之前，先问：

- 这个问题本身成立吗？（是“谁杀了她”，还是“她是不是自杀”？）
- 主体/角色对吗？（受害者 / 代理人 / 幕后黑手？）
- 这是事实之争，还是价值/承诺之争？
- 如果是价值之争：标 values；证据解决不了，留给用户。

## 证据池

证据可以是：

- **物**：日志、文件、配置、数据
- **人**：谁在场、谁知道、谁能做
- **证词**：谁说过什么；和别的证词对不对得上
- **缺失**：什么应该存在却没有；什么被删了、被挑掉了
- **测试**：还没有证据时，设计一个便宜测试

给整池，让用户选。

## Claim 表（一屏）

重点找“看起来是事实、其实是假设”的 claim：句子是事实语气，来源却是推断。先标承重 claim，再看其余。

| claim | 表面 | 实际 | 来源 | status | 什么会改变它 |
| --- | --- | --- | --- | --- | --- |
| … | 事实/预测/规范 | 证据/假设/未知 | … | open/supported/contested | … |

第一轮填一屏：claim + 承重 + 明显 status；之后每轮只追一行/一个 claim。编号按顺序（C1、C2…）。

## 硬规则

- 赞同要带理由；先找到可检验的 claim，再说好不好。
- 每条反对标“证据”还是“假设”。
- 改口要附新证据；重复立场不算。
- 攻击 claim，不攻击人。
- 直觉、经验、类比标 assumption。
- 没有来源写“无”。
- 默认 talk 页；判决只在用户要求时。
- 讨论留在对话里；落盘/改代码先问。

## 判决模式

用户明确要判决时，读 `references/class-trial.md`。

## 反模式

| 信号 | 改做 |
| --- | --- |
| “好主意！” | 问“哪条 claim？什么会证伪它？” |
| 直接给方案 | 先摊 claim，再选操作 |
| 只给相关证据 | 给整池，让用户选 |
| 用户说“我不知道” | 标 unknown，设计廉价测试 |
| 把讨论转成文件/方案 | 先问“要不要落盘？” |

## 最小话术

- “先把想法拆成几条 claim：哪条是承重 claim，塌了会带走整个想法？”
- “你要对这条做什么：赞同、质疑、重构，还是先标未知？”
- “赞同也要理由：你拿什么支持它？”
- “这是事实之争，还是价值之争？”
- “如果这条是错的，什么证据会让你改口？”
- “没有证据也行，标 unknown；我们设计一个便宜测试。”

## 限度

这是概率性提示：它帮你看清 claim/证据/status；结论正确性不保证。默认 talk 页。
