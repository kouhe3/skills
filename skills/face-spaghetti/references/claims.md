# claim 与快照

一次探测 = 一个 claim。机制、普查、性能、仪器四类 claim 各有自己的三行。入口在 `SKILL.md` §2.1，仪器侧见 `instruments.md`。

## 机制 claim

`SKILL.md` §2.1 的三行（假设 / 两个互斥预测 / 机器判据）。假设行附**置信度**：

| 级 | 条件 |
|---|---|
| 高 | 关键前提有 L2+ oracle，且已量 A/A 地板 |
| 中 | 有 oracle，未量 A/A |
| 低 | 仅 L1，或只能主观判断 |

置信度描述 claim 本身；结论的可信度按尺度分（`SKILL.md` §5），两者不混用。

## 普查 claim

产出是**覆盖表 / 通过数**而不是真假命题（造仪器、量覆盖率、扫全量语料）时，三行换成：

1. **范围**：覆盖哪个集合（关卡 × 指标）+ **观测单位**（调用点 / 函数入口 / 行 / 采样帧）；明确排除什么（录制不可用、共享日志、随机关卡）。
2. **oracle 版本**：录制/二进制指纹，地面真值来自哪条链路。
3. **判据命令**：一条命令给出逐项二值 + 地板（A/A；量化下限见 `instruments.md` I21）。

普查不产生假设：不写两个互斥预测。预注册行写「范围 + 判据」，跑完状态记 `快照`（`SKILL.md` §8），不写 `已证`。

**先交定义域表，再谈覆盖。** 普查的「范围」来自判据定义域表（`coverage-domain.md`，从代码 / 数据枚举），独立于台账与仪器。表里未测项默认 `unmeasured`，不并入「通过数」；下面的三桶只是缺口分类，不是完备性证明。

**先抽样再全量**：全量前在 **3 个单元**上走一遍「快照行」的四条自检钩子；缺一条就不全量。

**阳性对照先行**：从目标集合挑 ≥3 个**必然执行**的单位（脚本 cfunc、每帧回调、启动路径），正式采集里必须 `hit > 0`；全 0 说明仪器或窗口失效，先修仪器。

**未覆盖分三桶报**：`仪器看不见`（结构上不可观测：没有直接调用点、只走虚表/闭包/函数指针、跨模块不可拦）+ `语料没走到`（可观测但路径未覆盖）+ `窗口没覆盖`（执行发生在基线之前/之后或另一个会话：启动、退出、被截断的采集）。三桶下一步不同：换仪器或合成扫描 / 补语料 / 扩窗口。

**A/A 是集合差。** 同一单元两次独立运行算 `hit > 0` 的**对称差**：地板 > 0 是正常的（单次回调 / 定时路径）；差集函数名与地板写进快照，超过地板才判仪器 / 窗口失效。单次命中可以进并集，差集成员不进稳定覆盖；回归用两次独立运行的差，不用单次集合。

**覆盖取并集。** 单轮命中数不是覆盖：每轮与历史 counts 并集后再报，新增项单列，集合表随轮更新；单轮数与并集数分列，不混在同一列。

**单元要能归因。** 一单元一进程、各自 counts，每单元 `nonzero > 0`；整份语料塞进一个进程只报总数等于放弃归因。采集侧的存档/进度处理见 `instruments.md` §0.2。

**观测单位随仪器换**：claim 是「从未执行 / 死代码」时，调用点计数只数直接 `E8`，函数入口计数把闭包、虚表、函数指针都算进来——前者为 0 不能支持后者。

## 性能 / 规模 claim

三行之外另加两条：

1. **热点由 profiler 或采样定位**：微基准只证明「这段能快」，不证明「它是瓶颈」；判据同时钉住输出与时间——同一输入的输出指纹逐字段相同 **且** wall 下降。
2. **并发度 / 线程数 / 批大小实测至少一档**：算术下界不是预测；报告 wall 与总工作量。

## 仪器 / 工具 claim

写/提交 `tools/` 或等价仪器前，先预注册这一行；三行换成：

1. **合成正例**：能产生反例的入口（已知必然发生的调用 / 异常 / 状态切换）。
2. **负例**：真开关——坏输入 / 越界参数 / 关闭钩子，必须报差。
3. **真实宿主**：只作第二层验收；机制成立标 `已证（机制）`，不把「工具能跑」写成行为等价。

输入仪器的**标定 claim** 与行为 claim 拆两行：标定行判「标注点压住实际对象；错误 y 轴 / DPI 必须报差」；行为行判「按住 → 移动 → 事件 / 位置」。不用「拖动成功一次」反推坐标正确——那可能只是碰巧落在容差内。

## 快照行

`快照` = 覆盖表 / 通过数一类**随构建变化**的测量。行内带构建指纹（二进制 md5 / commit / 语料版本）与四条自检钩子：

1. 语料标识 + 仪器版本；
2. 每个单元的产出非空（`delta > 0`）；
3. 快照边界：基线取在动作**之前**；
4. 观测单位 + 窗口（调用点/入口；启动→退出 / 基线→结束）。

同一范围出了新快照，旧行置 `过期`——台账里只留一行真话。`快照` 里的 0 只读作「本窗口内未观测到」；要支持「从未执行」，用覆盖启动→退出的入口级仪器，并把窗口写进快照。

**快照也会写错。** 状态变化后必须重跑普查；旧快照置 `过期`，新快照另起一行。旧快照的桶计数 / 哈希本身错误（例如状态还没落盘就采集）时，旧行标 `已证伪` + 删除线，追加勘误快照；不手改数字，不整行重写。

## 依赖桥与 Wrapper 例外

**依赖桥（B 不可测时）**：A 依赖 B、B 暂时造不出判据时，「B 测不了 ⇒ A 也不写」是错误结论——拒绝写会让 A 永久卡死。A 可以先用**显式桥**接上 B，但桥必须标 `STUB(UNMEASURED)`，不许假装自己是实现；B 本身仍是 `blocked`，桥只解除 A 被 B 卡住的阻塞。六条同时成立：

1. 代码内标 `STUB(UNMEASURED)`，同一处写明输入、输出与失败行为（非法输入 / 未知分支 / 未实现路径怎么走）；
2. spec / plan / backlog 用同一标记，并写回流条件：B 何时可测、怎样换成真实现、换后重跑哪条判据；
3. stub 不计实现进度，不冒充 B 的实现，不作 B 的行为证据；
4. 经 stub 得出的 A 结论只标 `partial`（部分覆盖）/ `reacher-only`（只到得了目标态，不作行为证据）/ `unmeasured`，不标 `已证`；
5. B 可测后替换 stub 并重跑 A 的判据，替换前的结论不沿用；
6. stub 默认 fail-closed 或可配置（默认拒绝 / 默认关闭），不静默返回「成功」。

缺一条回到 `blocked`，按 `SKILL.md` §7 第 3 条落回流条件。收口检查：源码里每个 `STUB(UNMEASURED)` 都要在 plan / backlog 有同标记与回流条件；报告出现 `已证` 而结论依赖 stub → 违例。stub 被观测到的行为单列 `UNMEASURED`，不混进 A 的 PASS 条件；桩的等价性上限见 `instruments.md` §3（返回 plausible 常量只到 `L2-A`）。

**Wrapper 例外（桥只替换外部依赖的返回值）**：A 的合同就是「按特定顺序 / 参数调用 B 并转发其返回值」，且 stub 只提供 B 的返回值 / 句柄时，A 的可观测合同可被完整判据覆盖、可升 `已证`；B 的内容与副作用单列 `UNMEASURED`。四条同时成立：① 判据比较**调用环**（顺序 / 参数 / 返回）+ A 自己的状态，不比较 B 的真实效果；② 语料覆盖 B 的返回成功 / 失败 / 空 / 缓存命中；③ spec 明写 B 的真实内容不测；④ 报告不声称 B 等价。B 的返回值不被消费时，接收侧（窗口过程 / 子类 / 回调）要有 marker 计数证明调用真的发生。

下游 live 路径仍有差异（分派表漏 case、命中 / 绘制顺序）时，只锁 wrapper 的前缀：签名取 `ret + 转发环 + trace[:1]`，把差异的首个索引写进 fact，下游记 `UNMEASURED` + backlog。

## 收口条件

**reacher-only 检查点**：UI 上不可达的分支（只能从某个不可触发的 dispatcher 入口进入）标 `measured` 需要三件同时成立：

1. **真实路径不读**：仪器计数证明宿主对该参数的读取次数为 0，不是「看起来没走」；
2. **函数面覆盖**：A/B 覆盖该分支本身，引用 leaves / fact，含必失败负例；
3. **宿主无此路径**：fact 写明宿主为什么不需要实现这条路径。

缺一项保持 `unmeasured` + 回流条件。不要把「宿主没实现」当已测，也不要把「函数 A/B 绿」当 UI 可达。

## 台账粒度

- **一个 fact 只回答一个问题**：机制（为什么/能否）与覆盖（多少/哪些）拆两行。机制行 `已证（机制）`/`已证伪`，覆盖行 `快照`；混行时 `快照` 掩盖机制结论，四条自检钩子也无处安放。
- **快照行缺一不可**：语料/构建指纹、观测单位 + 窗口、基线时点、每单元 `delta > 0` 自检（见上文）。缺任何一条只能标 `待证`/`已证`，不能标 `快照`。
- **`STUB(UNMEASURED)` 是标记不是状态**：不能替代 `待证` / `已证` / `已证伪`；带该标记的实现只支撑 `partial` / `reacher-only` / `unmeasured` 结论，不作其依赖项的行为证据（见上节）。
- **`integration` 不升级状态**：函数级 A/B 仍依赖 canned / stub 时，真实 API 的 integration 只补该维度；替换 stub 并重跑同一 A/B 后才升 `已证`。宿主行为行（如 `host:*`）与函数状态分开记。
- **实现缺口与证据缺口分开记**：写了实现、指不出判据 = 实现缺口（项目里常写 `impl`）；有判据、仍有未测或 stub 维度 = 证据缺口（`partial`）。两者都不进 `已证`；状态迁移（含降级后恢复）追加勘误行，不覆盖旧结论。
- **旁路判据的 fact 要带变异证据**：结论落在旁路（overlay / 外部调用 / 计数器 / 日志）时，出处列写「只改旁路的变异 + 首分歧字段」，机制行标 `已证（机制）`；只有「两侧相等」而无该变异时最多 `已证（行为）`，并在影响列写明该副作用维度仍 `unmeasured`。
- **掩码只掩随机段**：同一行里既有随机字节又有确定字段时（加密文件 `size` + `sha256`、时间戳 + 其余字段），只掩随机那个 token、保留可复现的字段；整行掩掉等于把判据降成「有输出」。
- **后补判据优先加独立反算**：扩既有 lane 时，新语料的期望值用 `hashlib` / 独立公式重算（oracle 只当第二意见），不要把 oracle 输出抄成 cell——那是把「两侧相同」写成「两处相同」。
- **改被依赖的实现要重跑依赖方**：抽共享模块 / 修 callee（表函数、哈希、加密层）后，除新 lane 外必须重跑**所有**间接依赖它的 lane（实测：改完 `is_emoji` 后 `tdjson_diff` 仍须 `failures=0`），否则「修好了一层」无从证明。
