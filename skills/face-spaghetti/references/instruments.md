# 仪器（instrument）手册

一次性探测回答一个问题；**仪器**让同类问题以后都变便宜（差分 harness、转发/代理层、抓包器、布局探针、重放语料）。它和原型的区别：**别人能重跑**。

本文件是造/改仪器、以及报结论之前的清单。规则主干在 `SKILL.md`；个案机制在 `lessons.md`。

**按类型读**：§0.1–§0.12 各是一种仪器，造哪种只读对应小节 + §1 自证清单，不通读全篇。

## 0. 一台仪器合格的定义

进 `tools/` 时，docstring 必须写明四件事，缺一件就不算仪器：

1. **命令**：怎么跑（输入路径 / 环境变量 / 前置目录）。
2. **判据**：PASS/FAIL 或期望输出（阈值、首个分歧）。
3. **覆盖边界**：它**看不见**什么。
4. **失效条件**：依赖哪个版本/布局/接口；上游一变即置 `过期`。**仪器失效比结论过期更危险**——它还在跑、还在输出，看起来一切正常。

规模超过一次会话能审完的代码就不算探测：拆成「最小可判真假」的一半先跑。

## 0.1 常量表生成器（从 oracle 录制生成代码常量）

适用：被测系统的构造常量是**计算值**（π 的倍数、1/128 网格、累加结果）。手抄十进制必漂 1e-5 级，而判据容差常在 1e-6。

纪律：

- 通过 oracle 轨迹把「调用」与「产物」对齐，按 (调用, style/变体) 聚合；先做**同键逐位一致**检查，不一致就拒绝生成并报出分歧的输入——不一致往往意味着结构里有栈残渣/未初始化字段。
- 生成物入仓，头部写「由 <工具> 生成，勿手改」；生成器带 `--check`，判据是**与仓库文件逐字节相同**，不是「能打印」。
- 生成器不给自己打分：判据仍是下游差额对拍（首个分歧 / 总数=0），生成器只负责把常量变成可重放的产物。

## 0.2 入口探针：把「从未执行」变成可判

适用：覆盖 / 死代码 claim，而现有仪器只 patch 直接调用点（Lua VM、虚表、函数指针全漏）。

命令：目标清单 → `gen_targets`（逐条定序言长度 + 生成 patch 表）→ 编 DLL → 注入器/代理装载 → 按周期把 raw counters 落盘 → 报告脚本映射回 VA。

**逐单元采集**：目标按关卡/场景分单元时，一单元一进程，各自 counts（可归因、可 resume），每单元要求 `nonzero > 0`；全量前先抽样过门（`claims.md` 普查 claim）。共享存档/进度是环境输入：先读活动存档的解锁范围，要改就整文件备份、批次后恢复并核对指纹。

做法：每个目标函数入口写 `jmp stub`；stub 内 `lock inc dword [counter]` → 重放被覆盖的序言字节 → `jmp target+L`。stub 里不加 `pushfd`：ESP 必须保持入口值（序言可能有 `[esp+4]` 取参），flags 不是调用约定输入。

判据：`installed=N failed=0`；阳性对照 ≥3 个必然执行的入口 `hit > 0`，且覆盖**安装窗口两端**——启动期入口 + 稳态入口，安装日志成功不等于挂载时机正确；两次独立运行的 `hit > 0` 集合取**对称差**，≤ 实测地板（单次回调常见为 1）即合格，差集函数名写进出处，> 地板先修窗口/仪器（计数随帧率浮动，判据取集合）。

覆盖边界：只覆盖目标表；序言含相对跳转、长度 >24 B、或存在 `(target, target+L)` 内部入口 → 生成器跳过；1 字节 nullsub 无法挂桩；安装前已执行的调用不计。

失效条件：目标二进制换版（全部 VA 失效）、ASLR / 非固定 ImageBase、patch 字节不是完整序言。

## 0.3 合成契约探针（synthetic contract）

适用：语料有**结构盲区**——采集层过滤（例：只读 getter 占日志 ~60%，默认丢弃）、宿主从未调用的入口。录制只能证明被观测到的调用，不能给未观测入口上判据。

命令：两侧各一子进程（崩了算失败，不毁会话）→ 固定序列 → 输出 `steps` 与 `exported=N/M` → 逐项对比；退出码 0 = 一致。

做法：

- **每入口至少一次**：从导出表/符号表取全集，序列里每个名字都要点到；覆盖集合进输出，缺一个就 FAIL。
- **合成 vtable 夹具先枚举间接调用点**：跑之前把被测函数里的 `call [reg+off]` / `call [imm]` 全列出来，逐槽映射到夹具字段并写 cb（清单进 case 注释）。缺槽的症状是 UI 线程**挂起**（跳 0），不是 mismatch；环长度不等先查路由缺口——返回值 / 终态一致不代表路由完整。
- **夹具与仪器共用 arena 时先公布布局**：环 / 日志的固定偏移是保留区，夹具结构从空闲高段分配；把根对象放进保留区会被每 pass 的 ring reset 清零（症状是跳 0 挂起或假绿），不是被测函数问题。
- **指针比符号**（world/body/shape/joint 的注册名），不比地址；浮点给固定相对容差，整数/字符串精确。
- **A/A + 负例**：同一实现两次必须 0 差；再把一个入口的机器码改成固定返回值（按 **PE/ELF 导出表**查地址——旁路 CSV 的 rva 可能偏），探针必须报差。
- **返回类型按真身读**：`bool` 只写 `AL`，按 int 读会把 EAX 高位垃圾当值——这类导出只比低字节。
- **签名/布局没有第二来源时**：逐字节/逐参数置 1 + 最小可崩调用定槽位，再用反汇编确认；「跑通」不等于对。
- **步进场景要干净**：多个关节叠在同一对 body 上是病态约束（oracle 会出 NaN）；物理/回调片段另起简单场景。

覆盖边界：只覆盖 API 层（返回值/出参/对象类型/状态回读/回调是否触发），不含真实时序；与录制互补。

失效条件：导出表增删、宿主可见结构布局改动、固定序列里的对象生命周期顺序变化。

## 0.4 首次异常记录器（first-chance crash recorder；Windows 例）

适用：宿主崩溃只弹窗/退出码 0，拿不到异常现场；或注入 DLL 后偶发 AV，日志只剩「成功」与「退出 0」。

命令：在目标进程内装 `AddVectoredExceptionHandler(1, …)`（先于 SEH/LCL），只在环境变量开启时启用。VEH 内同步写：
`EXC code/addr/模块+RVA/params`、`CTX`、`FRM/SCN`（EBP 链 + 栈扫描）、`MOD`；可选 `MiniDumpWriteDump`；
可选轮询本进程 `#32770` 的正文（覆盖没有 OS 异常的 Pascal `raise`）。每条记录 `WriteFile` + `FlushFileBuffers`；
默认只写第一份 dump，进程随后弹窗/退出/被杀都不丢。

判据：① 合成正例：`__try/__except` 吞掉的 AV、`RaiseException` 参数、x87 invalid（子进程，`0xC0000090`）；
② 负例：不设开关不建文件、正常启动 0 条 `EXC`；③ 真实宿主主线程 AV 的日志含 code/模块+RVA/≥2 条宿主栈帧/MDMP。
三条都过才算仪器可用。

**必做自噪声过滤**：`IsBadReadPtr/WritePtr/CodePtr` 内部用 SEH 探测不可读页，会先抛 first-chance AV；
记录器会把它们当成崩溃，日志被同一地址（例：`KERNEL32!IsBadReadPtr+0x2E`）刷满。记录前按这三个函数入口
`+0x80` 字节范围过滤；过滤后跑一次正常启动，确认 `EXC=0`（噪声地板）。

覆盖边界：只抓 OS 异常；FPC `raise`/`EAbort` 这类无 OS 异常的路径只剩 `#32770` 正文，raise-site 栈已 longjmp 展开；
进程在注入前/记录器安装前崩溃看不见；栈是「候选返回地址」，需再用 map/IDA 符号化。
失效条件：OS/dbghelp 版本、`IsBad*Ptr` 实现变化、导出/模块基址变化；换机重跑合成正例。

## 0.5 对象/VMT 探针（`Self` 到底是什么）

适用：反编译出一批函数，`EAX` 看起来像对象指针，但不知道 `Self` 的类/布局；或要把函数拿到进程内 A/B 调用。

做法（FPC/Delphi）：`[Self]` = VMT；`VMT+0` 实例大小，`+4` 父偏移，`+8` 父 VMT，`+0xC` 类名 Pascal ShortString 指针，
`+0x30+4*i` 第 i 个虚方法。类名读法：ShortString 首字节长度，后接名字（`T...`）。一个函数出现在多个 VMT = 继承；
沿 `+8` 父链、同槽号逐一比较，直到父 VMT 的同槽不是该函数，这一层就是**定义类**；运行时 `[Self]` 的类名可能是子类。

先判调用约定，再谈 `Self`：

- Pascal 方法：`Self@EAX`（FPC register）。
- FPC register helper：第一参数 `@EAX`，可能是 `lua_State*`/普通指针，不一定是 Self。
- Lua C 入口（`lua_CFunction`）：cdecl，`lua_State*` 在 `[ebp+8]`，不是 Self。
- `__stdcall`/`__fastcall`：按声明取参，EAX 无隐式 Self。

仅凭「函数开头保存 EAX」不能断定 Self；要看是否 `[eax+off]` 访问对象字段、调用点是否把对象放 EAX。

判据：已知 VMT（构造器写入或已知对象）读出的类名与源码/运行期一致；同一函数的多 VMT 归到唯一定义类；
非虚方法的调用点 `mov eax, <Self>` 与函数 `[eax+off]` 的偏移范围相容；负例：静态函数/`lua_CFunction` 不应被标成方法。

覆盖边界：VMT 只覆盖虚方法；非虚方法/静态函数不在表里，需 call-site 数据流或字段布局；
类名短字符串/父链布局是 FPC 2.2.4 的，Delphi/其他版本偏移不同。
失效条件：编译器/框架版本、VMT 布局、类名指针位置变化；换版本先用已知 VMT 做一次自检。

## 0.6 状态帧 A/B（静态绘制列表）

适用：两个渲染器/场景实现要在**同一状态**下比「画了什么」，而像素受 DPI/遮挡/采样影响。先把一帧还原成 draw 列表（prim / texture / 顶点 / UV / alpha），再逐 draw 比。

命令：两侧各抓一份 draw 日志（prim / texture / 顶点 / UV / alpha）→ 各取一个帧 → 纹理 id 按像素 CRC 映射回素材名 → 逐 draw 比 bbox/UV/alpha；仪器自带 `--self-test`（合成 A/A + 对一个 draw 做已知平移）和两份**独立采集**的 A/A。

判据：`pairs=N mismatches=0 missing=0 unmatched_ref=0`；A/A 先量静态 draw 地板；动态 draw（提示淡入、齿轮电机、悬停层）单独报地板，不混进静态判据。

覆盖边界：只覆盖录到的关卡/状态/帧；鼠标光标等输入相关 draw 显式排除；纹理 id 必须映射到素材名（上传顺序不可比）；「同一关卡」不等于「同一瞬时态」——动画中间帧不是稳定状态，优先取稳定帧或把瞬时字段写进判据。**bbox 相等不证明旋转/朝向等价**：轴对齐四边形 + bbox 尺寸也能过 bbox 判据；要判旋转就比顶点或至少比第一条边的方向，否则把旋转态单列。

失效条件：日志格式/帧边界/纹理上传顺序变化；素材 CRC 映射 miss；状态字段/输入时序变化。

## 0.7 闭环输入仪器（GUI/鼠标/拖拽）

适用：唯一可用的驱动是合成输入（点击/按住拖拽/键盘），而状态转移没有可调用的命令入口；或要证明「光标驱动的玩法路径」。

一台合格的输入仪器 = **状态回读通道 + 坐标标定图 + 分阶段驱动**，三者缺一不可：

1. **状态回读**：每步一份小 digest（对象 id→位置/角度/事件/状态机），控制回路只读它。全量 FFI 日志的解析放在阶段之间——pre/post 每条记录会把日志推到 GB 级，解析还会阻塞输入，症状是「鼠标根本没动」。代理/抓包层可加 `LIVE`（每步 flush）与 `LIGHT`（只写 digest）开关；默认关闭，不改变原日志格式。
2. **坐标标定图**：截客户区，画所有刚体编号+世界坐标、目标十字、预计轨迹；标注点必须**压住实际对象**（几何重合），否则先改映射：
   - 客户区尺寸/原点是**物理像素**；进程先 `SetProcessDpiAwarenessContext(-4)`，比例按抓图尺寸算（I12）。
   - 视口从被测程序自己的 `GetRealViewRect` / 相机参数反推；**屏幕 y 与 GL/世界 y 的朝向**单独验证（常见：`screen_y=(bottom−world_y)/(bottom−top)·h`）。
   - 标定图同时画一个已知世界点（origin/视口角）与鼠标当前位置，读图即可看出偏移。
3. **分阶段驱动**：`start`（起进程+进关+状态落盘）→ `shot`（标定图）→ `drag`（读状态→算光标→按住→每步重读）→ `status` → `exit`（干净退出+恢复共享资源）。每步落一张图；控制回路里只做「读小状态+发输入」，截图/重解析放在阶段之间。

4. **输入-owned 状态与异步 settle**：如果目标/按键/光标字段由引擎输入循环每帧刷新，外部 `WriteProcessMemory` 会竞态；改走进程内 API/代理注入（同一物理世界直接 ApplyForce/SetVelocity）或调用引擎自己的 update。`level state` 先于菜单关闭；动作前等 0.5–1 s，并复查 `level + menu + 控制器已 arm`。完成态分两层：**物理完成**（body/事件）与 **UI 完成**（对话/面板，含计时/动画），分别记录、分别判；物理完成不能替代 UI 验收。

5. **力模式 vs 速度模式**：PD 力可能被墙顶住/很慢；先量施力点与接触，再选速度伺服或 waypoint。两种模式各自要有 A/A 与负例（不 arm / 错方向 / 错施力点），不能混在一张表里。

### 私有桌面的输入与观测边界

- **窗口句柄按桌面生效**：从另一个桌面 `PostMessage` 返回 `ERROR_INVALID_WINDOW_HANDLE`（不是「消息丢了」）。驱动必须在目标进程内部：控制通道命令里 `SendMessage(WM_MOUSEMOVE)` / `SendMessage(WM_LBUTTONDOWN)`，或客户端注入 helper 线程。
- **WndProc 没有 `WM_MOUSEMOVE` 分支 ≠ 拖拽不可合成**：只发 `down → up` 失败时，先补 `down → 4×mousemove → up` 再判。WndProc 可能只显式处理按键消息，但合成 mousemove 仍能经内部消息路径 / 定时器更新 drop 目标；只发 down/up 会把「输入序列缺一步」误判成「需要真实鼠标」。
- **全局光标查询看不到私有桌面**：`GetCursorInfo` 反映活动桌面的光标，私有桌面里的 `SetCursor` 不改变它。判据改成进程内记录：IAT hook `SetCursor`/`LoadCursorW`，记 `(fn, arg, ret)`；分类按**身份**——与进程内新加载的 stock 光标（`LoadCursorW(NULL, IDC_*)`）和 app 资源（`LoadCursorW(inst, L"DownArrow")`）逐一比对，跨进程只比分类名，不比句柄值。
- **真模态框的自动应答要留事件**：应答线程点按钮（`BM_CLICK` + `SendMessageTimeout`，带 deadline/force close），`HCBT_ACTIVATE`/`HCBT_DESTROYWND` 各发一条 `dialog_open`/`dialog_close`（含控件树）；判据是这两条事件加之后的存档状态，不是控制命令的返回值。
- **`WM_COMMAND` 直投不关 MessageBox**：`MessageBox` 的对话框过程只认按钮通知；`PostMessage(hwnd, WM_COMMAND, IDOK, 0)` 会让框一直挂着。要点 `GetDlgItem(h, IDOK)` 后 `BM_CLICK`；找不到目标按钮时显式回落到默认按钮，并在记录里标明回落。
- **先见证再比较**：0/0 可能来自「两侧都没触发」。每例先断言目标效果存在（恰好一个 box / 预期控件 id / 事件条数 / `s_calls>0`），再比流；witness 失败时直接 FAIL，不进入流比较。
- **模态菜单/对话框的观测用桌面内子进程**：控制通道拒绝 modal 菜单 id 时，在私有桌面 `CreateProcess(..., lpDesktop)` 起子进程，`EnumWindows` 找主窗口，`PostMessage(main, WM_COMMAND, id)` 打开 `#32770`，读 `GetClassNameW`/`GetWindowTextW`/`GetWindowRect`/`GetClientRect`/`EnumChildWindows`（id/class/text/style/enabled/visible），点 IDOK 关闭并确认主窗口存活。判据只收内容面；`window` 尺寸、控件 1px 偏移、图标像素这类环境差写 `deltas` 并留回流条件（实测：同一 `ShellAboutW`，宿主窗口 574×501 vs oracle 563×491，client 相同 559×464）。
- **驱动点击本身会进模态时（赢/输局）**：控制通道的 click 会在 UI 线程同步执行并停在 `DialogBoxParamW`，命令永远不返回。改由同一桌面内子进程投下决定性点击、轮询 `#32770`、dump 控件树后应答（`WM_COMMAND 7` / `BM_CLICK`），控制通道只用于点击前后读状态；负例只改「不画面/不画框」这类旁路，不改状态。
- **表面像素在桌面内抓（A/B 双表面）**：`BitBlt(GetDC(hwnd))` 只有在**目标桌面的进程里**才拿到用户眼前的表面——从交互桌面侧调用会受限或得到黑图（I29 的「私有桌面像素全黑」往往就是这个，而不是 BitBlt 本身不可用）。做法：`lpDesktop` 子进程里先 `InvalidateRect(hwnd,NULL,TRUE)`+`UpdateWindow(hwnd)` 强制一次全量重绘，再 `BitBlt` + `GetDIBits` 写原始 `w,h,BGRA`（top-down）；同一脚本再以「不强制重绘」抓第二张。判据 = 两侧「当前表面」逐字节 0 + 两侧「强制重绘后表面」逐字节 0 + 每侧 A/B 也 0（重绘幂等）。原始 DIB 直接比字节，不需要图像库/编解码；`PrintWindow` 只代表「重绘输出」这一面。负例在**状态不变**的前提下只改绘制（例如让 paint 跳过某个子图），断言 diff 精确落在该 bbox；另用「子图区非背景像素数 > 阈值」的 witness 防止两侧都是空白也 0/0。

- **瞬态覆盖层不适用这套双表面配方**：只在「当前表面」存在的效果（抓牌预览、拖动 ghost、悬停临时高亮）会被 `InvalidateRect+UpdateWindow` 擦掉——强制重绘抓到的不是当前画面。改用三张：base = 覆盖层出现**之前**的强制重绘（先证它与同一时刻的当前表面逐字节 0，即重绘幂等）、overlay = **不重绘**的当前表面、restored = 撤销/松开后的不重绘表面。判据 = 每侧 `overlay vs base` 的 diff ≥ bbox 面积下界（效果见证，两侧各判）+ 每侧 `restored vs base` 0/总面积 + 两侧同帧逐字节 0；「overlay == restored == base」判 FAIL，不是 PASS。

### 真人类输入 lane（合同禁止合成修饰键时）

**预检（先做，再让人上手）**：

- **触发链实测，不信 surface 文案**：静态调用链 + 一次合成探针。命令菜单里的某项不等于「那个对话框」：菜单命令可能只 `PostMessage` 一条自定义消息，真正的对话框在胜利 / 结束动画末尾的调用链里。人按菜单没看到框时先查链路，不记人为失误。
- **干净进程优先**：IAT 替身会吞掉真对话框（`MessageBoxW` stub / 对话框 stub）。human lane 默认跑无注入的 oracle 进程，只做注册表快照 / 恢复 + 外部观测；必须在注入进程里跑时，给替身加一个「放行真消息」开关，默认仍 stub，并留一条「stub 生效」自测。
- **替身先判 arena 指针**：记录型替身把实参写进固定 arena（如 16 KiB A/B 区）时，必须拒绝 `arena == NULL`。A/B 之外的 live / human lane 从不分配 arena，第一次真对话框的症状不是「被吞掉」而是进程 AV（秒级退出，看起来像「没有框」）。自证：注入进程弹一次真框 + 读退出码。
- **失败注入按返回地址定向**：按 API 名失败会先被同 API 的另一条路径（paint vs drag）消费，症状是「fixture hits=1 却没有框」。hook 里用 `_ReturnAddress()` 只在目标调用点返回失败，并把 `ra_last` 写进结果——它能在不上人手的情况下证实 / 证伪触发点（能把候选 API 从 A 纠正为 B）。
- **坐标系先打印**：DPI-unaware 进程的 `GetWindowRect` / `GetClientRect` 是逻辑像素，交互桌面屏幕 DC 是物理像素；屏幕抓图 / ROI 乘 `DESKTOPHORZRES / GetSystemMetrics(SM_CXSCREEN)`。客户区 `BitBlt(GetDC(hwnd))` 与窗口矩形同口径。selfcheck 先断言 client 尺寸与 scale，再抓像素。
- **证据按 run 命名**：launcher 只覆盖运行副本（exe / dll / state / reg backup），**不 `rmtree` lane 目录**；产物用 `result-<branch>.json` + `<branch>-*.bmp`，不同分支或两次独立进程互不覆盖。
- **watcher 先起，提示后到**：后台 watcher 先采样 / 等对话框；提示框只列人工步骤；人做完回到提示框提交，事件已被捕获，不要求提交时目标进程仍在后台或前台。
- **菜单身份看 popup HMENU**：`GetGUIThreadInfo.hwndMenuOwner` 只证明「有菜单」；`EnumThreadWindows` 找可见 `#32768`，`SendMessage(MN_GETHMENU)` + `GetMenuItemID/StringW` 读项集合。负例 = 无匹配助记键不出菜单。
- **状态分类用结构 ROI**：模态框遮住整屏中心，用不被遮挡的客户区 ROI 分类（以实测两态像素率定阈值），不要用整窗 digest；动画结束态可能是**空桌**（元素全部落出屏幕），不是「基础满」。
- **私有桌面动画不推进 ≠ 不存在**：同一条消息在活动桌面会播放，私有桌面多帧全同只说明该桌面的输入泵；human lane 触发动画时留足等待时间（>2× 实测）。
- **`reg export` 带 hive**：`reg export HKCU\Software\...`；`winreg.OpenKey(HKEY_CURRENT_USER, r"Software\...")` 用子键。崩溃后先 `finish` 恢复，再重跑 lane。

当唯一路径是真人键鼠（例如 `SendInput` 被合同禁止、`WM_KEY*` 直投不更新 `TranslateMessage` 的线程键态）：

- **只提示，不投键**：用独立 TaskDialog 告诉人按什么；提示进程退出后把目标窗口 `SetForegroundWindow`，不要用提示框抢焦点。判据里写清「human lane 不进默认 gate、与其它 GUI 测试串行」。
- **键见证**：`GetAsyncKeyState` 轮询记录每个键的 down/up、时刻和**当时的前台 HWND**；要求序列键的 down 全落在目标窗口。只看「效果出现」会把投到其它窗口的键算成通过。
- **停止键会留在队列里**：动画泵用 `PeekMessage(PM_NOREMOVE)` 看见停止键就返回，但**不出队**；紧随其后的确认框会消费这条按键（Esc → 以「否」关闭，框可能只存在 <1 s）。因此框的见证改用 `IsWindowEnabled(owner)==FALSE` 的模态态（并接受抓拍失败），不要要求人再点一次；停止后的终态也不要假设是「中断的中间态」——结束动画的元素可能已全部离场。
- **提示框输出编码**：TaskDialog 包装的 `label=` 可能是 UTF-8，而父进程按控制台代码页解码；按本地代码页读会把标签读成未匹配，lane 直接走 cancel。先 UTF-8、失败再本地代码页。
- **鼠标见证**：同一轮询记录 `VK_LBUTTON/RBUTTON/MBUTTON`；lane 期间任何鼠标按下都判 **invalid run**，不是行为差。真人为了聚焦 / 关菜单的误点会改选中态，制造假的 oracle/host 分歧。
- **清理前取状态**：负例（无效果）在发 `WM_CANCELMODE` / Esc 关菜单**之前**读状态；清理动作本身可能写字段。把 `after_key`（按键后、清理前）与 `after_cleanup` 分开记录，判据只用前者。
- **菜单 / 模态见证**：`GetGUIThreadInfo` 的 `GUI_INMENUMODE` / `GUI_POPUPMENUMODE` 证明菜单确实打开；对话框用 `EnumWindows` + `EnumChildWindows` 读 class/title/client/style/控件树。正例 = 预期对话框出现且控件树两侧相等；负例 = 非助记键（不是 mutant）不出框。
- **旁路负例**：宿主行为变异（如「该 no-op 的键改成退出」）仍要给 mutant；真人 lane 的 mutant 断言是「进程按预期退出 / 不退出」，并保留自动近似输入 lane 作旁证。
- **连续 human 步骤之间等按键全部松开**：上一步的修饰键还按着就开下一个框，下一步的 key-down 见证会缺。每步开始前轮询 `GetAsyncKeyState` 直到所有修饰键 up，再取该步的 `start_idx`。
- **每步基线在异步初始化之后取**：对话框 `WM_INITDIALOG` 可能在窗口出现后才填字段；用对话框焦点事件 / 短暂 settle 后再取 `state_open`，no-op 判据用 `state_open == state_during`，不要拿整条 lane 的初始状态。步骤本身合法的状态推进（如取消写 seed）只要求最终两侧相等。
- **no-op 步的树判据收窄到行为面**：只比 id/class/text/visible/enabled/相对 rect；控件 `style`/`exstyle` 差异另立任务（例如对齐方式、边框样式），不要为了全绿把可见差异并进 no-op fact 或静默过滤。

判据与自证：

- **阳性对照**：按住已知必然可拖的 body，读回位置必须变化；**负例**：错误 y 轴/DPI、松开按键、错误 body id，三者至少各报一次差（真开关，不是「没输出」）。
- **闭环**：循环 = `read body → cursor=target → send input → read body`；固定轨迹只在状态通道确实不存在时用作**探针**（结论只写「该轨迹通过/失败」），不当仪器。
- **A/A**：同一轨迹两次独立运行，记录目标 body 的位置差与事件序列差（刷新/完成/关节创建）；地板写进四件套。固定 wall-clock 的帧数不可作判据（I22）。
- **共享资源**：存档/配置先备份；前台窗口、鼠标按键状态、残留进程、日志文件句柄都是「环境干净」的一部分（SKILL §2.2）；退出走干净路径，失败再强制并记录丢了多少。

覆盖边界：只覆盖观测到的关卡/对象/轨迹；输入通道（前台/DPI/按键采样窗口）与未观测关卡都不外推；像素只用于标定，行为判据回到状态/事件。

失效条件：客户区尺寸/DPI/窗口样式变化、视口参数变化、代理日志格式升级、输入轮询帧率变化。

## 0.8 合成输入夹具（数据/关卡/录制）

适用：被测对象消费数据文件（关卡、脚本、录制、配置包），而真实样本的场景/谜题太复杂，或没有覆盖你想测的对象组合。合成夹具自选对象与输入，取代「逆向真实样本」。

命令与判据（两段，缺一不可）：

1. **容器可逆**：`roundtrip` 读→写→与原文件**逐字节相同**；`rebuild` 同名替换后读回条目内容等于输入，`verify` 的计数/偏移不变。
2. **oracle 加载**：把夹具放进 oracle 的副本目录（只读原件不动），用产品自己的加载入口读回状态；判据是对象集合/位置/事件与夹具声明一致，不是「没崩」。

做法：

- **同名替换**（复用现有记录/slot）优先：不新增条目、不改清单/索引；要新对象就改夹具内容。
- 夹具里的完成条件写成产品侧可观测的**状态标记**（回调里 teleport/创建/改字段），日志或 digest 读得到；像素留给默认桌面的验收（I29/I30）。
- **完成阈值与验收阈值分开**：夹具在完成阈值处触发动作，记录指标会被它截断；验收阈值严格高于夹具阈值，两者的关系写进用法。
- 夹具进仓库的测试目录（默认 `tests/`，tracked），一次性生成器进 gitignored 探测目录（默认 `work/`），副本目录与输出包同样 gitignored。
- **参考录制的输入要 pin**：录制时没固定住的输入（栈残渣字体 / 时间 / 随机种子 / 真实注册表残留）会让参考自己漂；录制侧注入同一份计划输入（pin 生成器 + md5 + `--check`），证明 pin 下参考可重现，判据命令显式带 pin。
- **生成器与 live 语料先对齐再上指纹**：给旧语料加 `--check` 常立刻报 mismatch——live 语料可能是某个未入库的生成器版本产出的。先判差异类别：语义差（字段 / 布局）优先**反推生成器**逐字节重建 live 语料（保住既有证据）；只有换行 / 序列化差才统一格式后重写。不为「让 `--check` 绿」重新生成语料，那会作废引用它的 fact。
- **每例播种用已有的通用命令**：per-case 输入走 runner 的通用写状态命令就够，语料字段只描述语义，槽位写全、与 case 顺序无关；上下文块放不下时走文件 token，并在入口校验长度与 magic。
- 负例：不加载夹具时对象集合不同；改夹具里的一个坐标，oracle 读回的值跟着变。

覆盖边界：只覆盖夹具声明的对象/输入组合；oracle 真实样本的行为不外推；容器格式/加载入口变化时重新 round-trip。
失效条件：归档格式升级、加载入口/记录字段变化、只读原件被改写。

## 0.9 对话框/模态驱动与调用 ABI

适用：被测对象会进 `MessageBoxW` / `DialogBoxParamW` 等真模态，或 A/B 用 `ab_callN` 直接调函数。

### 驱动

- **驱动线程**：控制命令线程往往持有 busy 锁；模态驱动放在**进程内独立线程**，用 `WH_CBT` / `EnumThreadWindows` / `GetGUIThreadInfo` 找 `#32770`，用 `SendMessageTimeout(BM_CLICK)` / `WM_COMMAND` / `WM_CLOSE` 关框，带 deadline + force close。**禁止跨线程 `EndDialog`**，也不要把 `SendMessage` 打给主窗口。
- **填控件要在 `WM_INITDIALOG` 之后**：用「对话框可见 + 控件存在」当状态信号（不用固定延时），否则 proc 的初始化会覆盖你填的值。
- **按调用序号给值**：一次 modal 调用取一个（末值重复），才能覆盖「返回 0 → 再弹一次」的循环分支。
- **没有 Cancel 控件的模板**：用 `WM_COMMAND MAKEWPARAM(IDCANCEL, BN_CLICKED)` 模拟 Esc；别指望 `BM_CLICK` 找到按钮。
- **模态会泵 `WM_PAINT`**：被测函数 `InvalidateRect` 后进真模态时，对话框循环会把上一条 case / 上一 pass 的更新区画出来（A/A 红）。每 pass 先 `ValidateRect(hwnd,NULL)` 清更新区，再让函数自己制造更新区。
- **指针 vs 序号按量级分类**：`DialogBoxParamW` 的模板参数 > `0xFFFF` 才算字符串指针，否则当序号；传裸 RVA 会被记成 `ord=...` 并静默走 canned 路径。S 必须传与 oracle 同类的值，环里 `tpl/ord/proc/parent/init/ret` 逐项比较。

### 调用 ABI

- **按 `argc` 分派**：`ab_callN` 依赖被调方 `ret 4N` 自清栈；1 参用 `ab_call1`，4 参用 `ab_call4`，其它 argc 直接 fail-closed。错误调用形状可能崩在栈上，也可能静默写坏对象——先归因仪器，不先改被测函数。
- **按被调方 `ret N` 配平**：naked 桥 push 了参数就必须有人清——被调方的 `ret 4N` 或桥自己 `add esp`。对以 `ret` 结束的寄存器 ABI 函数用不 push 参数的那支（`ab_call_reg0`），否则 epilogue 把 saved ebp 当返回地址，症状是挂死而不是报错。S 侧 `__cdecl` 按 `is_cdecl` 用类型化调用，不复用 stdcall 桥；计划替身每 pass 重新 arm。

### 每 pass 复位与 live

- **复位面 = 环 + 计数器 + live + scratch surface**：`pn==0` 不得沿用上一条 case。返回「上一状态」的 op（`GetPixel`/`SetPixel` 的上一个像素、`SelectObject` 的先前对象）还要求每 pass 把 scratch 位图 / 状态重画成同一内容，且这次重画要在记录窗口外（`active=0`），否则 A/A 必红。
- **真实子调用要把 live 纳入复位**：把 canned 依赖换成真实函数体后，复位面扩到全局、状态板、缓存句柄、注册表 overlay；A/A 漂移先查这些字段是否被上一条 case 改过。
- **常驻 live 环另开开关**：`SetCursor` / `SetCapture` / `ShowCursor` 这类在一条命令内成对出现、返回时已复原的调用，A/B 期间的环看不见；建常驻环（ctl `arm` / `dump`，与 A/B 的 per-pass 开关互不复用），两侧各记后用**身份**比较（`SetCapture` 的 arg 是否 = 本进程主窗口，`ReleaseCapture` 无 arg），并把「宿主重写同一函数」纳入对照：重写只保终态会漏掉这三件。判据 = 环逐条相等 + 一条只关该分支的变异；同一路径还有第二可观测通道（像素 / 状态 / 另一条环）时，**每个通道各配一条只关该通道的变异**并断言其它通道仍绿——只关绘制的变异才能证明像素判据不是靠环顺带绿的。
- **失败分支用内层注入**：依赖函数体保持真实，只在内层 API 注入失败（返回 0 / NULL / 错误码）来构造失败路径；canned 整个依赖会同时抹掉成功路径、调用环与真实副作用。
- **live 初始化是判据的一部分**：台账命令里的初始化参数（开局 N 步的「设选项 + 初始化 + settle」）照抄执行；未 settle 的启动动画会让 A/B 挂死在固定 seq、进程单线程 100% CPU、控制通道不再应答（I35）。
- **破坏性 API 在窗口内吞掉**：卸载进程内库这类调用真做掉会让后续 case 全部失效；只计数 + 参数进判据，真实拆除单列 `UNMEASURED`。

### 真实消息泵与真实窗口（把脚本输入换成 OS 输入）

- **泵要移出控制线程**：`GetMessageW` 在控制命令线程上会与 ctl 事务抢同一个队列。把被测入口放到独立 worker 线程：worker 先建自己的队列（`PeekMessage(PM_NOREMOVE)`）并置 ready，控制线程 `SetEvent` 后等待；每个 pass 新建 worker，窗口也在该线程创建（`DestroyWindow` 必须回创建线程）。加 watchdog：超时向该线程 `PostThreadMessage(WM_QUIT)` 解卡，超时计数进判据，不静默。
- **队列前的噪声先排空**：真实 `ShowWindow` / `UpdateWindow` 及自定义消息会 post 绘制 / 显示消息；在投放计划消息前先 `PeekMessage` 排空，否则计划位置被噪声顶掉，`GetMessage` 的计数与计划长度对不上。
- **真实 HACCEL 只吃键盘消息**：`TranslateAccelerator` 只对 `WM_KEYDOWN` / `WM_SYSKEYDOWN` 命中；用 app 自定义消息做「accel hit」只会 miss 后照常 dispatch。hit/miss 用例改成真 `WM_KEYDOWN('A')`，命中与吞掉的证据是「无 DispatchMessage 记录」而不是 marker 计数。
- **OS 产生不了的返回值单列故障注入**：`GetMessageW=-1` 之类错误返回无法由真实队列构造；保留一条显式注入（记录在案），其余用例必须是真队列，报告写清哪一例是注入。
- **真实窗口用每 pass 影子类**：被测代码按名创建 / 复用窗口类时，直接真建会撞进程里已有的注册 / 单例。hook 把类名换成每 pass 新注册的影子类（proc 平凡），真 `CreateWindowExW` / `ShowWindow` / `UpdateWindow`，pass 末 `DestroyWindow` + `UnregisterClassW`；句柄（返回码、全局槽、Show/Update 参数）折成同一 token 再进 A/A。
- **嵌套销毁要回投**：`WM_CLOSE` 由 `DefWindowProcW` 调 `DestroyWindow`，后者的 `WM_DESTROY` 必须回投给**同一实现**（窗口 proc 按 pass 路由），否则只测到窗口拆除、测不到真实关闭链（资源环 + 退出 post）。每 pass 记录嵌套销毁次数并进 A/A。

### 发行构建与测试构建

- **用户可双击的产物不能默认进私有桌面**：测试宿主常默认 `CreateDesktop` + 控制通道。加一个只作用于发行配置的宏：无 `--desktop` / 环境变量时留在交互桌面且不建控制通道；测试仍靠显式开关拿私有桌面与通道。两条路径各跑一条 smoke（交互桌面可见可关 vs 私有桌面 0 窗口 + 控制通道可用），否则「发行版」只是带 debug 行为的测试壳。

### 比较面与归一化

- **比较面 = 声明的可见范围**：对话框 title / 控件树 / 按钮 / 返回码之外，还要有 `EndDialog` 的 nResult（次数 + 序列）与 `DialogBoxParamW` 返回值。只比坐标、把 `SelectObject` 之类参数清零，等于声明这些调用不可见——被测合同包含它们时，这种签名会让错误实现全绿；能上整环（fn/nargs/args + handle mask）就不留专用签名。一个两边都不读的 ctx 字段是假测试。
- **对象身份**：裸句柄每 pass 重分配；按身份 / 非零 token / 资源 id 比较，live-only 句柄只读回。跨模块字符串按内容哈希，不按指针。
- **指针参数归一化成 token**：先判 R/S 是否指向同一块内存；各自模块的静态缓冲不是，就归一化成同一个 token、内容另存文本比较。给 S 加导出返回缓冲地址，别猜地址，也别因为指针不同跳过整个环。
- **非幂等 API 只记参数**：`EnableMenuItem` / `ShowWindow` 返回「先前状态」，跨 pass 必然变；环只记参数与次数，返回值不进 A/A。要判效果另读状态并在每 pass 复位。
- **共享副作用在窗口内吞掉**：默认音频端点（`MessageBeep`）、自投递 `SendMessageW(WM_CLOSE)`（会销毁 A/B 窗口）记录后不转发；真实效果单列 `UNMEASURED` 并另做独立测试。开关默认转发、每 pass 复位。
- **可忽略的 OS 调用也要有环**：合同包含 `GetMenu` / `InvalidateRect` / `MessageBeep` 这类无返回值调用时，没有环 = 坏实现跳过也全绿。为每个语义上可缺的调用加小环（op + 参数 + 次数），只在窗口内 active。
- **每 pass 独立窗口要重映射 raw 句柄**：销毁 / 重建语义下每 pass 一个新 HWND；快照前把该 pass 的窗口值折成固定 token，`IsWindow` 逐 pass 进 A/A/match（该销毁的必须已销毁、该存活的必须存活）。
- **聚合字段只代表最后一条 case**：pass 收尾才写的汇总在多 case 运行里只剩最后一条读数；要逐 case 读数就拆成单例语料重跑，或让仪器按 case 累加并逐条回填，并在报告写明口径。
- **新增 per-pass 播种键要有一对只差该键的 case**：键表、允许表、复位循环三处任一漏改都会静默退回默认值；用「同一状态、只把新键在 0 与非 0 之间切换」的对照证明播种生效。

### 替身、输入与判分

- **计划替身：确定、终止、按名分派**：返回的字符串自己保证 NUL 与确定字节（REG_SZ 的 `cb` 含 NUL）、未写区清零；按调用名 / 参数选返回值，不按调用序号；R 的 IAT hook 与 S 的 ops 读同一份计划、写同一个环；每 pass 清空计划与环。
- **替身写目标前判可写**：调用方可能把 `const` 字面量当输出缓冲（编译产物 / 源缺陷），真实 API 会 AV；替身先 `VirtualQuery` 目标页，不可写就按「无数据 / 失败」返回，并把该分支记 `unmeasured` + 回流条件。不要为了让分支可达去改调用方的常量，也不要让 A/B 把 oracle 写崩。
- **命令通道的失败必须写新结果**：状态码 error + 未写 JSON + 已递增序号 = 客户端把上一条 body 当新成功。dispatch 前清空结果缓冲；客户端再按命令名 / 长度校验一次。
- **一个 IAT 槽只能登记一个 hook**：hook 表里同一 `dll!func` 出现两条时，第二次 patch 会把第一条的 hook 当 real（或覆盖），症状是递归 / 绕过 / 启动窗口丢失。新增前先按 `dll+func` 查重，把新语义合并进同一函数，用 `armed && measurement_window` 分支隔离。
- **回调写调用方缓冲时，替身要写配置块**：`call [obj+off]` 的合同是出参时，通用记录 cb 只返回不写，两侧的未初始化局部与初始化局部就会分叉；加一个「按 op 回写出参」的夹具（把配置字节写进第 N 个参数指向的缓冲），并在每 pass 复位。
- **一次性 API**：三 pass 在同一个进程；一次性真实 API（如 `RegisterClassW`）只有第一次成功，后续返回「已存在」。A/B 用 canned 返回值 + 独立 integration 覆盖真实语义；替换 canned 前函数只到 `partial`。
- **转发 API 的送达证明**：返回值不被消费时，「吞掉」与「真调用」在环上同形；在接收侧（窗口过程 / 子类 / 回调）加 marker 计数并进 A/A/match，否则只算参数记录。
- **同一状态多副本**：ctx 内嵌副本与独立字段可能不同步；单函数 A/B 把两份种成一致，组合调用才暴露旧副本。组合层在子函数入口 / 绘制点同时记录 live 与子函数实际 ctx 的副本，先证明副本相等再谈调用顺序。
- **S 只按 live 后态判分**：把 S 的 ctx 当答案等于让 S 自己出题。判分读 live 内存 / 真实窗口文本，并要求 S 写回 live；代价是负例也必须错在 live 上——只改 ctx 的坏 S 会变成不可见。
- **oracle 读未初始化栈时，计划钉在它实际读取的位置**：例如某 API 只写 `pv`，调用方却从 `pv+0xE0` 拷字体——hook 要把计划写到 `pv+0xE0` 才能让 R 稳定且与 S 同输入；真实内容单列 `UNMEASURED`。
- **S 的桥只写 ctx 时，oracle 落到 live 的必须镜像回 live**，并有一条与默认基线不同的 case 证明镜像生效（默认值恰好等于基线时，没镜像也全绿）。
- **大块输入走文件通道**：控制通道有单条命令长度上限；上下文 / 语料块用文件 token（`ctxfile=` / `regseed=`），入口校验长度与 magic，缺输入 fail-closed。

## 0.10 像素 / 表面判据（客户端 vs 全窗口 vs 真实表面）

适用：外观、文本、NC 边框、主题控件；以及「状态相同但担心少画 / 多画」的残影类 claim。

先做**三路捕获对照**（同一状态，同一进程）：

| 路径 | 看得到 | 看不到 |
|---|---|---|
| `PrintWindow(PW_CLIENTONLY)`（或 `WM_PRINTCLIENT`） | 客户区完整重绘 | 画到 `GetWindowDC` 的东西（状态栏文本、NC 装饰）；增量绘制残影 |
| `PrintWindow(0)`（全窗口） | 标题栏 / 菜单 / 客户区（合成重绘） | 私有桌面上未真正合成的子控件；真实残影 |
| `BitBlt(GetWindowDC)`（真实表面，仅活动桌面） | 真实增量绘制、残影、已合成控件 | DWM 合成的标题栏：读到的是窗口位置的壁纸像素（随位置变），不可跨窗口比较 |

**目标元素必须在判据所用路径里可见**，否则判据是空转。

- **画到 `GetWindowDC` 的文本**（如状态栏）：客户端 `PrintWindow` 不含它；判据取 GDI 事件（`TextOutW` 的 x/y/text）或全窗口表面。事件的「最后一条 text」才是可见串，前面可能是背景色擦除的旧串（随重绘历史变，不参与等价）。
- **NC 两态（active/inactive）**：`PostMessage(WM_NCACTIVATE)` **不改变**真实前台状态（实测两态全窗口图像逐像素相同）。要真实 `SetForegroundWindow`，用 dummy 窗口做失焦态；每次校验 `GetForegroundWindow()==目标`，被前台锁拒绝时判**无效**而不是通过。负例不要用 `return 0`（系统会拒绝切走，失焦态不可达 ⇒ 仪器失效），用「完成状态切换但跳过重绘、返回 TRUE」。
- **私有桌面 vs 活动桌面**：私有桌面适合纯客户区 / 表面（`PrintWindow`），但「控件只在真实合成后出现」的 lane（对话框按钮、非客户区激活态）必须放活动桌面，并在 docstring 写清；其余 GUI 测试仍串行、仍不进默认 gate。
- **冗余调用 ≠ 输出不同**：两侧 live 环不等时先比最终表面 / 状态。可能一侧 7 条 draw、另一侧 19 条而最终客户区 0 差（重复画了被覆盖内容）：记 backlog（允许还是删除冗余重绘），不要为了环相等删 draw。负例仍需能改变**可见**输出（surface 分歧也算检出）。
- **判据三件**：同状态 A/A（两次独立采集）、阳性对照（换一个明确不同的状态，断言目标区域像素 / 事件确实变）、必 FAIL 负例（只改被测语义）。文本 lane 的正例要覆盖「不同内容确实不同」。
- **宿主内自检**：每条 UI 动作后把当前 surface 与「同一状态完整 paint 一遍」比较（绘制期间静音事件流，否则污染 A/B 判据）；负例故意去掉一处重绘，自检必须报 `diff_px>0` 与 bbox。这是局部残影最稳的判据。
- **单帧不是测量（I41）**：全窗口捕获里的子控件（按钮 / 复选框）会整块随机缺失，两侧都会发生；像素 lane 的「一次快照」必须先证明同一侧连拍 k≥5 帧稳定，比较用众数帧并把 `votes` 写进结果。单帧 0 差只证明那一帧，不证明 lane 可重复。

## 0.11 进程入口 A/B（WinMain / DllMain / main；startup ring）

适用：被测函数是进程入口，或只能跑一次、没有可重复的调用者。进程内二次调用会在「类已注册 / 窗口已存在 / 单例 / 静态初始化已完成」处早退，复测不到真实路径；把入口当成 **startup lane**，不要当普通 callee。

命令：每 lane 一个 fresh process；两侧同一 registry / env / clock / show / args。在 `ResumeThread` 前装 IAT hook 环。把入口包装器里的唯一 `call <entry>` 改成**同签名 wrapper**（同调用约定、同 `ret N`）：wrapper 调 oracle 或 S 的实现，返回前 `mark_end(ret)`，调用方栈契约不变。没有可替换的 call 时，退到**首个 `GetMessageW` 冻结 + 进程退出码**，把 return 记 `unmeasured`。失败早退没有窗口可读通道时，在 `mark_end` 把环写文件，不要依赖控制通道。

环：每条外部调用记 `(id, canonical args, ret, out-buffer, string)`；句柄 / atom / HACCEL 只记「等于前一条 X 的返回」的 source bit；类 / 窗口 / 计时器 / 加速键 / `PostMessage` 的字段进环；入口返回的 `ret` 单独记。窗口绝对 x/y（`CW_USEDEFAULT` 级联）不判，判 client / window w/h 与相对几何。

自证：两次独立 oracle 环逐字节相同；正例 `done=1`、`call_patch=1`；每个 lane 至少一条只改被断言事件的 mutant（跳过终态 post、错 style、跳过分支），首个分歧必须落在该事件。

陷阱：

- **静态 CRT（`/MT`）的 `time` / `srand` / `rand` 不经过 IAT**，hook 环看不见。用显式桥或动态导入，并确认 oracle 与 S 的 CRT 随机状态同源。
- Release 可能重排相互独立的外部调用（实测 `InitCommonControlsEx` 被移到 `LoadIcon` / `LoadImage` 之后）；调用序 claim 要 `#pragma optimize("", off)` 或序列屏障。
- 入口里的「post 出去」属于本函数；post 之后的消息处理 / 绘制 / 自动行为属于下游。不要把下游终态并进入口 claim，另立 backlog。
- 预注册的常量回反汇编核对（实测 `AdjustWindowRect` 第三参与预注册值相反）；反汇编与实测冲突时改台账，不改观测。
- 失败早退（class / window / timer）与 `hPrevInstance != 0` 需要入口参数注入 / failonce；没有就记 `unmeasured`。

覆盖边界：本 lane 只锁入口自己的外部调用序、副作用与返回；入口之后的消息循环、`TranslateAccelerator`、WndProc / 绘制另按各自 fact 判。

## 0.12 S 侧旁路对称、cell 负例与 live 路由缺口

复刻侧（S）与 oracle 同进程时，S 的 API 调用走**自己的 IAT**，oracle 的 hook 看不见。

- 每条可观测调用都要有 S 侧桥（`SOL_*` 一类命名），S 直调 → 环为空 → A/B 假分歧。踩过 `MoveWindow`、`DialogBoxParamW`、`TextOutW` 一类。
- 桥必须走**同一 hook**（记录 + 行为），不要只写 arena：只填 arena 时几何事件恒空；只回 stub 时对话框结果恒空。
- cell 负例用**独立 mask 传输**：变异开关用 `strtol` 解析会把 `0x80000000|bit` 钳成 `LONG_MAX`；高位语义又会与旧门冲突（门把要测的分支一起关掉）。做法：用两个 16 位 lo/hi 参数 + `strtoul`，cell 位与旧标志分开。
- 负例失败先查 **mask 是否真的到达**：环 / 返回没变，可能是旧门把 mutant 掩盖。
- **live 路由缺口**：分派表漏 case（某个 op 缺成功 / 失败回退）在合成 A/B 里看不见——fixture 不经过那条 case。用真实状态 cell 的**全环比对**暴露；先补路由，再重跑 cell。
- 反汇编 `sub eax, N` 作用在**已减过的** eax 上；按字面推 `je` 映射会错位。先写清每条跳转对应的 op，再改代码。
- 长 cell 表加 `--only <cell>`：单 cell 跑少量进程，避免整表重跑。
- 下游 live 路径仍有差异时，cell 只锁 wrapper：签名取 `ret + 转发环 + trace[:1]`，下游单列 `UNMEASURED` + backlog（见 Wrapper 例外）。

## 0.13 外部 oracle 的适配清单（同一份代码，两种调用者）

被测对象只能通过自己的 TU、自己的生成代码、自己的常量表访问时，探针与真实调用者之间的差异会伪装成「实现差异」。逐条先查：

| 症状 | 机制 | 处置 |
|---|---|---|
| 私有类 / 匿名命名空间里的类拿不到 | 符号只在那个 `.cpp` 的 TU 内可见 | 探针 `#include "<被测>.cpp"`，链接加 `-Wl,--allow-multiple-definition`（与已构建静态库里的同名符号共存）；构建命令写进探针文件头 |
| 随机分支每次采样都一样 | 函数内 `static`（如 `get_default()` 的 op 树）一个进程只构造一次 | **每样本一个新进程**；同进程跑 N 次只证明确定性，不证明分布。要覆盖随机分支集合，样本数 × 分支数一起算 |
| vector 元素读不对 / 报 `Wrong vector length` | 生成器有两套：`TlFetchBoxed<...>`（带 `0x1cb5c415`）与 `TlFetchVector<...>`（**裸 count、裸元素**） | 构造语料前先读生成代码的 `X::X(TlParser&)`，按它写，不要按 TL 规范猜 |
| 指纹 / 摘要差几个字节 | 具体类的 `tl_store_unsafe` **只写字段**，构造号在 boxed 外层 | 复刻序列化时先确认「这个 API 写不写 ctor」；差 4 字节 = 多写或漏写构造号 |
| 库自己的 key 表能加载，我造的另一种 PEM 头却行为不同 | 同一入口（如 `PEM_read_bio_PUBKEY`）接受多种头（SPKI / PKCS#1），真实调用点只用其中一种 | 语料从**真实调用点的常量**（源码里的字符串字面量）取，不按格式规范造 |
| 文案里的列表格式对不上 | 容器的 `operator<<` 是 `{a, b}` 不是 `[a, b]`，空表是 `{}` | 打印格式先实测一次，再写进另一侧；不要按语言习惯猜 |
| 两侧行内容相同、整串不等 | C++ `printf` 在 Windows 输出 `\r\n`，Rust/Python 写 `\n` | 比较前统一 `replace("\r\n", "\n")`；与台账文件行尾那类问题不同源，不要混用处置 |
| 含非 ASCII 的 argv 两侧不同 | C++ `main` 的 argv 是 ANSI 代码页，Rust 是 UTF-8 | 参数走 hex / base64；或两侧都用 `CommandLineToArgvW` + `CP_UTF8` |
| 长输入构造不出来 | Windows 命令行上限 32767 字符 | 探针支持 `-` 从 stdin 读 hex；长边界（如 35000 字节）只走这条路 |
| 同一脚本文本两侧输出不同字节 | 参数进制不一致（C++ `tokens >> unsigned int` 是十进制，另一侧误用十六进制解析） | 脚本格式写进探针文件头，两侧按同一进制解析 |

前五条会**静默**给出错误语料（不报错、只是内容不对），后五条会给出**假分歧**。两类都要在第一条 DIFF 出现时先过一遍这张表，再怀疑被测实现。

## 1. 自证清单

仪器自己错时报出的"目标缺陷"是它自己的缺陷，而且**不报错、只给结论**。所以自证写进流程，不靠运气。

| # | 自证项 | 判据 | 失败症状 |
|---|---|---|---|
| I1 | **A/A 地板** | 同一份输入、同一个 oracle 跑两遍，差值就是地板；任何"有差异"必须显著高于它 | 把末位噪声写成缺陷 |
| I2 | **oracle 自检（含覆盖自证）** | 两件事都要：① 把真实序列重放给 oracle 自己，差异不≈0 就弃用该仪器；② 日志里必须出现被测阶段的标记（init 段 / 首 step / ≥N 个对象）。缺 ② 时，「差异」先归因为「oracle 没跑到」 | 地板无穷大 ≠ 差异很大；把「录制没跑到被测阶段」当成目标缺陷 |
| I3 | **计数也要 A/A** | 计数类判据先让 oracle 跑同一份输入，量出地板 | 地板内的计数被当成证据 |
| I4 | **自证不能循环** | 拿"上一轮跑出来的数"复现自己只证明确定性；必须配**测前答案已知**的对照 | bug 被原样复现一次，然后写进台账 |
| I5 | **保真度** | 配对是否 1:1、dump 长度是否覆盖最坏情况、缓冲满/进程被杀丢多少——三个数字写进用法 | 抓到的比实际的少，且看不出来 |
| I6 | **落盘自证（flush）** | 每条记录一次写盘；周期 flush 要能关；用**计数非零**证明，不用"日志文件存在"证明 | 短命进程/单帧被抓成"零调用" |
| I7 | **拦截面** | 覆盖 = **静态导入表 ∪ 动态解析**；动态解析的每次结果单独记，并记下指针落在哪个模块 | 拿到函数指针就以为能看见调用 |
| I8 | **窗口/帧边界** | 逐帧比较前先证明**两边日志里都有帧标记**（swap/帧事件）；没有边界的日志只能整段比 | 逐帧比的是对齐假象 |
| I9 | **可开窗** | trace 类仪器必须能按 step/请求区间门控 | 全量 trace 到 GB 级 = 没有仪器 |
| I10 | **簿记配对** | 仪器自己维护的对象表要有删除事件 | 只增不减的簿记会 dump 已释放内存，产出成百上千条**假差异** |
| I11 | **驱动类阳性对照** | 能"发命令"的仪器（合成消息/注入/模拟输入）先跑一个**已知必然生效**的最小动作 | 没反应时分不清是对象坏还是通道不通 |
| I12 | **单位与坐标系** | 用法里注明输出单位、坐标系、与被测进程 DPI awareness 的关系；比例按**抓图尺寸**算；先打印 `DESKTOPHORZRES/逻辑宽` 与 client 尺寸——DPI-unaware 下窗口矩形是逻辑像素而屏幕 DC 是物理像素，两条路径不能混比 | 物理像素被当逻辑像素，点击按错误倍数偏移 |
| I13 | **修好后重跑历史** | 仪器口径一变，基于它的旧结论全部作废重算；新旧不混在一张表里 | 两个口径的数是同一张表的行 |
| I14 | **便宜指标排序 + 贵指标裁决** | 先用便宜指标（字节相同率、位移）预排，再对前几名算指令级相似度 | 便宜指标直接下结论会假阴性 |
| I15 | **坐标系统计写清分子分母** | 跨两个坐标系做覆盖率必须说明分子来自哪边、分母来自哪边，并做一个**会崩的对照**（把对象放到绝不可能匹配的位置，数字必须掉到 0） | 分子分母取自不同坐标系，覆盖率虚高并被当成"已收敛" |
| I16 | **哨兵值检查** | 凡「恒 0 / 恒空 / 恒常量」先查哨兵与过滤条件 | 负值被当哨兵滤掉，结果恒 0 |
| I17 | **判据的度量必须匹配机制** | 先问"这套机制里哪些字节必然不同"（地址、指针、重定位），排除后再比；几何判据写清比的是 bbox / 顶点 / 边方向——bbox 相等不证明旋转/朝向等价 | 把"同码"判成"有差距"，进而推出"链接了不同单元"；旋转过的四边形与其轴对齐外接框同分 |
| I18 | **写回执 ≠ 生效（含静默 no-op）** | 每个写操作/工厂调用后用**独立读接口**复验（挂断点→列断点、暂停→读状态、写值→读回、建对象→数下游产物）；工厂/绑定不报错、不崩溃也可能 no-op（句柄为空/未初始化），同样按失败处理 | 接口报 "success" 但目标状态没变；建对象成功却数不到产物 |
| I19 | **控制面失效 → 改持久化状态** | 写操作不可复验时，改组件自己的持久化格式离线写入，重启后只读确认（§5） | 继续在协议层加补丁：几百次往返仍没挂完 |
| I20 | **边界来自轨迹事件，不是人工计数** | 用轨迹自带的阶段标记切段（首次 step / 首个 swap / 结束事件）；人工 limit 只作临时手段，且必须在用法里注明「limit 是猜的」 | 人工计数漂移后，判据退化成对常数的拟合 |
| I21 | **量化下限：判据容差 ≥ oracle 的存储精度** | 先量 oracle 自己存成什么精度：float32 的 ulp 随幅值变（`\|p\|≈18` 时 1 ulp=1.9e-6）、定点的一个 LSB、采样的一个间隔。**容差低于步长时判据没有意义**——要么按 ulp/相对容差比，要么先证明实现落在同一精度桶。A/A 地板为 0 也不代表可以把容差压得更小：重复同一记录只证明确定性，不证明精度 | 把 1 ulp 的量化差写成缺陷；或反过来，把触到步长的真差异当噪声放过 |
| I22 | **时间与状态字段** | 每条记录带 `t / state / elapsed`（状态机另带 score 与 margin）；计数类指标先证明它与时间/帧无关——固定 wall-clock 窗口的帧数会浮动（同一命令两跑总调用差 3.6%、中位比值 1.0097），此时判据取**集合**不取计数 | 把「跑久一点」当收敛，或把帧数差写成行为差 |
| I23 | **观测单位一致** | 快照 / 表格必须写「调用点 / 函数入口 / 行 / 帧」；跨单位的数字不比较 | 649/1012（调用点）与 166/361（入口）被当成同一张表的两个数 |
| I24 | **独立 A/A + 合成负例** | 同一实现**两次独立采集**；同一份日志重放只证明解析；对一个字段 / draw 做已知扰动必须报差 | 同日志 A/A=0、独立 A/A 非零；或负例不报差 |
| I25 | **闭环与标定** | 输入仪器必须有每步小状态回读 + 标定图；标注点压住实际对象；正例（按住已知 body 会动）+ 负例（错 y 轴/DPI、松开按键、错 body id）各一条；控制回路延迟 < 一帧；判据取记录流的逐 step 极值/首个事件，不取回路轮询采样（轮询只决定下一帧输入） | 开环硬编码轨迹；把截图/全量日志解析放进回路，鼠标没动就卡住；用轮询最小值判「到没到」，快对象从两次采样之间穿过就假阴性 |
| I26 | **输入-owned 状态 / 异步完成** | 外部写引擎每帧刷新的输入状态时，先证明字段不被覆盖；完成态等 UI settle（level+menu+计时）；物理完成与 UI 完成分开判 | 写 target/button 被输入循环清零；level state 先到、菜单后关，完成态退回菜单 |
| I27 | **A/B 两侧实现级别一致** | 先对齐两侧实现级别（桩对桩、实现对实现）；一侧是桩、一侧是真实实现时，返回值派生的实参不可比——只比调用序 / 非派生参数，或把桩补齐 | 把 0 vs 9.09 的派生坐标差当成实现缺陷 |
| I28 | **采集失败分桶** | 超时 / 崩溃 / 空日志记 ERROR，瞬时失败重试并记次数；一致率只统计成功采集，失败不入分母 | 把采集失败算成一关不一致，或静默丢弃失败样本 |
| I29 | **私有桌面像素可能全黑** | 私有桌面隔离输入/窗口，但不保证 GL 前端缓冲可被 GDI/`PrintWindow` 抓到；返回 1 也可能是黑图。完成判据改用产品侧标记（I30） | 把黑图当截图成功；用像素判私有桌面的完成 |
| I30 | **不可观测完成用产品侧标记** | UI 完成/回调可能没有可读状态；在回调里改一个日志/digest 能读到的状态（teleport/创建/字段），比截图稳 | 用像素/延时猜完成；把标记前的分支当完成 |
| I31 | **仪器二进制版本门** | 装载前比特征串/md5 与当前 `build/` 产物一致；阳性对照覆盖安装窗口两端（启动期 + 稳态）；不一致或启动期恒 0 先换副本 | `installed=N failed=0` 却启动期全 0：用的是旧副本，缺后续新增的开关 |
| I32 | **A/B 先过仪器区间** | 首个分歧落在 setup/prep（句柄、颜色表、注入视图、采集环 / 表容量）时不出函数结论；每 pass 的 prep 摘要必须相等；环 / 表容量与溢出 / 回落计数进判据 | 把 prep 差当函数差，去改已对齐的函数；`A/A=0` 或逐例 `mismatch=0` 被当成行为等价 |
| I33 | **每 pass 复位与身份归一化** | 环 / 计数器每 pass `memset`，`pn==0` 不沿用上一条 case；裸句柄按身份 / 资源 id 比较，跨模块字符串按内容哈希 | stale 环上的「检出」被当证据；同一对象换号被当成实现差异 |
| I34 | **计划替身：确定、终止、按名分派** | 返回的字符串自带 NUL 与确定字节（REG_SZ 的 `cb` 含 NUL）、未写区清零；按调用名 / 参数选返回值，不按调用序号；每 pass 清空计划与环；R 的 IAT hook 与 S 的 ops 读同一份计划、写同一个环 | R/S 读到不同栈残渣，环里的文本带不同垃圾 ⇒ 永不消失的假分歧；回退分支错用第一次 `LoadLibrary` 的返回值 |
| I35 | **A/B 的 live 初始化就是判据的一部分** | 台账命令里的初始化参数（开局 N 步 = 设选项 + 初始化 + settle）必须照抄：被测函数读 live 状态时，未 settle 的启动动画会让 A/B 挂死在固定 seq、进程单线程 100% CPU、控制通道不再应答。判据：同语料在该初始化下连跑 N 次 0 挂起；省掉初始化做对照，把挂起率写进台账 | 把「跑不动」归因成被测函数死循环，或在不稳定 live 状态上录证据 |
| I36 | **替换 / 桩的假绿三件** | ① **命中计数**：被测 S 真被调用的次数 > 0 并写进结果；② **输入存在性**：每次 A/B 输出对象实际拿到的输入形状（模板名、控件 id + `present`、参数字节长度）；③ **旁路同向**：R 与 S 的注册表 / 日志 / 计数器写同一侧 | `s_calls=0`、正负例都 0/0 被当成等价；输入不存在时两侧都退化成 no-op；一侧写真实系统、另一侧写内存替身，事件流从第一个旁路调用起结构性分歧 |
| I37 | **判分读 live，不读 S 自己的 ctx** | 判分读 live 内存 / 真实窗口文本，并要求 S 写回 live；负例必须错在 live 上；早退分支每 pass 从同一份 pristine 快照恢复 | 把 S 的 ctx 当答案 = 让 S 自己出题；只改 ctx 的坏 S 变成不可见，测试照样全绿 |
| I38 | **控制面开关的通道自检（每入口）** | 启动 / 权限 / 发行模式的开关可能把测试通道关掉。改完按「无参 / 显式参数 / 环境变量 / test 标志」四个入口各跑一条，断言通道的有无与预期一致；**无参 lane 必须没有通道**，它同时是「永远开通道」这条过度修正的必失败负例 | 把「连不上」当被测对象崩溃；只改工具（加 `--test`）不查合同措辞；开关改动后只跑默认 lane |
| I39 | **容器级副作用按宿主调用点判据** | 已 matched 的 proc 只证明 S↔R；宿主自己的窗口 / 对话框创建会重写容器级副作用（居中、尺寸、焦点、owner、Z 序）。每个调用点单独判据：在目标线程内读 `GetWindowRect` / `GetClientRect`，用**公式推出的期望值**逐侧比实际（绝对坐标 run-specific，不能跨进程比），再比相对主窗 offset 与 client 尺寸。跨实现（宿主无模板）比窗口几何时，等式判据落**客户区**与内部布局；`window rect` 的差 = NC 区（菜单栏 / 边框），归宿主特性写 fact，不写成缺陷 | 用「S 已 matched」推断宿主位置正确；跨进程比绝对坐标；只比像素（客户区像素与位置无关，位置错了也全绿） |
| I40 | **旁路副本每次重入前都要刷新** | A/B 给 S 的 ctx 是 live 的副本；把消息真投递后的第二轮（self-post、路由窗口、嵌套消息）会以上一轮写过的旧副本为输入，而 R 直接读 live。做法：每次投递 / 重入前用 live 重刷副本并写回 live，判据 = A/A 0 + R/S 0；负例用 env 开关关掉刷新，必须复现原分歧 | 只在入口调用后刷一次；把「第二轮读旧副本」的分歧记成实现差异；用 A/A 仍绿来解释（A/A 只证可重复，不证输入同源） |
| I41 | **单帧捕获不是测量** | `PrintWindow(0)` 这类「请求重绘」的捕获对子控件不是原子的：同一对话框在同一侧连拍 8 帧，某个按钮可能 0–3 帧有、4–6 帧无、7 帧又有（两侧都会发生）。做法：每个比较对象连拍 k≥5 帧，取**像素众数**帧比较，`votes` 写进结果；最高票 <2 判 `unsettled`（不判差异）。`RedrawWindow(RDW_UPDATENOW\|RDW_ALLCHILDREN)` 有助但不能单独解决。判据：修前单帧假失败率、修后 N 次全绿、负例（只改被测文案）仍只打红对应对象 | 把单帧缺控件当成两侧差异 / 回归；用一次 0 差重跑宣布 lane 稳定；只加 sleep 不加帧数；两侧共用同一份「可疑帧」 |
| I42 | **全局输入的 pin 与夹具消费自证** | 被测函数的输入来自全局而非参数（根对象、布局全局）时，把合成夹具放进 arena 不等于函数会读到它。做法：① 每个 case 先把全局指到夹具、case 结束恢复 live 值；② 用**必然写回 arena 的变异**证明夹具被消费——positive 的写回落在夹具区，negative 的首差落在被改字段。若负例只靠返回值分歧而 arena 仍 0 差，先查函数是否仍读 live 全局 | 夹具建好但函数读 live 对象：A/A 与 S 全绿、负例靠 EAX 假过；pin 未恢复让后续 case 读到合成根，崩溃或静默换源 |
| I43 | **记录点必须与被调 API 的实参同一状态** | 记录「某 API 收到什么」时，取样点放在调用点、读实参本身；不要在调用之后读局部量——库或被调函数会改它。实测：在一侧于 `DrawTextW` 之后读 `r.right`（调用前已减过一次，调用后又减一次），记录值比实参少 41 px，其余字段全同、只有该坐标分歧；移到调用前即对齐。判据：同一次调用两侧记录的 rect 逐字段等于实参（先打印一次「实参 vs 记录」对比） | 把仪器取样点造成的差当成两侧布局差，去改绘制算法 |
| I44 | **IAT hook 条目必须自证「装上了」** | IAT patch 只对**导入表里存在**的函数生效；hook 表写一个未导入的 API 不报错，表现是该环恒空（易读成「产品不调用」）。同族函数也会造成误判：hook 了 `TextOutW`，产品实际走 `DrawTextW`，环里 `fn` 全为另一个值才暴露。做法：hook 安装后暴露每条的 installed 位（如 `hooked` 位掩码），lane 先断言「该装的都装了」再解读空环；hook 表与 `objdump -p` 的导入表交叉核对 | 把空环当「产品未调用」；用未导入的 API 写判据；hook 表加条目后不核对导入表 |
| I45 | **被测试替身吞掉的调用：判据取实参，不取副作用** | 替身（记录参数、返回成功但不执行）会让被测系统的结果永远停在旧值：oracle 的 `MoveWindow` 是替身，resize 后状态 rect 不变，只能比参数；host 侧真执行同一公式，状态才跟随。做法：① 判据 = 替身环参数（x/y/w/h/repaint）逐条相等；② 另一侧真执行并断言结果跟随，作为「参数有效」的对照；③ 台账写明「该 API 在 oracle 侧是替身」 | 比 resize 后的 rect（替身冻结，永远相等或永远不等）；把替身吞掉的副作用当产品差异；漏写替身边界，后来者以为测了真实窗口行为 |
| I46 | **单侧劫持不是对称替换** | live-object hijack（对象指针 / 子对象槽）只截获**经过该指针**的调用；S 若直接调用自己的 dispatcher，劫持对它无效。做法：① 先证两侧都命中（各自 dispatch ring 计数 > 0、首条 entry 存在）；② 行为 lane 用 record-and-forward（记录后调用原函数），router-only lane 用**两侧同源**的 canned 返回；③ 不要把 oracle 的单侧回调当 A/B 判据 | 把单侧劫持当两侧桩，S 的真实下游继续跑（或按默认返回走进无界路径）；路由器差异被下游崩溃 / 挂起掩盖 |
| I47 | **消息用例 ≠ 分支 cell** | WndProc 消息表的 lane 会命中提前门（某个全局 / 对象字段为 0）而根本没执行 dispatch 分支；转发 / 常量分支（`ShowCursor`、`DefWindowProc`、默认绘制、`WM_CLOSE`）没有可观测差异，坏实现与真实现无法区分。做法：按「消息 × 门控前置 × 入口」枚举 cell；转发 / 旁路 cell 加 spy（ShowCursor / DefWindowProc / PostMessage / EnableMenuItem 环）与必 FAIL 负例；否则只算 control-flow coverage，记 `unmeasured` | 用「若干条消息 ret/graph/post 全等」宣布消息表等价；mousemove / killfocus 落在提前门上，目标 op 从未执行 |

| I48 | **abort 类判据在 Windows 上要先压 WER** | 「这行会不会 abort」只能每例一进程比「有没有返回」时，`abort()` 走 fast-fail → WerFault，每次等待约 3.7 s；17 例 × 2 侧就能把一条 lane 拖到 100 s+，看起来像卡死。做法：父进程（仪器）先 `SetErrorMode(SEM_FAILCRITICALERRORS\|SEM_NOGPFAULTERRORBOX\|SEM_NOOPENFILEERRORBOX)` 再生子进程，单次 abort 降到约 0.1 s；判据仍是「子进程非零退出」，不比对 abort 文案（两侧运行时不同） | 把 abort 延迟当成被测物挂起；为省时间删掉 abort 例；改比 stderr 的 CHECK 文案 |
| I49 | **纯函数 lane 的第三重校验：独立公式反算 oracle** | C++ oracle 对 Rust 的两侧相等只证明「两边一样」，不证明 oracle 真在跑文档写的那条算法（探针把输入喂错、调错重载都会让两侧一起错）。做法：仪器里用一段独立的最小实现（Python 十几行：符号扩展 + 掩码、哈希累加、base64 分组）按文档重算每个 case，与 oracle 输出逐条比对；不一致先修探针。附带判据：空输入、边界值单独断言 | 只比两侧就宣布「算法已复刻」；独立实现照抄探针的结构（等于同一份错）；把反算写进产品代码路径 |

**放弃条件**：当一台仪器的准备成本超过它要回答的问题时，**换尺度**，不要换更硬的仪器。为拿一个定时器参数上调试器、被无关模块的加载事件反复打断，不如用「屏幕小块按固定间隔采样、统计画面变化率」——三行代码就能回答"渲染是按需重绘还是固定 tick"。

## 2. 判据取谁：副作用 oracle > 日志/内存 > 视觉

1. **副作用 oracle** —— 被测系统自己写出的状态：存档、配置、数据库、返回码、退出码。判断「这一关是否通过」读它自己写进存档的进度字段，比识别结算页稳得多，且完全不需要图像处理。
2. **日志 / 内存** —— 代理抓到的调用序列、内部字段转储。信息最全，但必须先过 A/A 与覆盖边界。
3. **视觉 / 听感** —— 像素、波形。只给「输出等价」，还受缩放、遮挡、混音影响；前两层够用时优先前两层，用这层时在结论里标尺度。

**视觉层的取样面先分清：表面 vs 重绘。** 三条捕获路径的可见范围、激活态与单帧陷阱见 §0.10：整机基线可用重绘，局部残影必须用表面；一次抓取不是测量，交互后 pending 重绘会让判据时绿时红，**连续两次抓取逐位相等才采信**（`stable_grab`）。私有桌面上的 `BitBlt(GetDC)` 只有在**目标桌面的进程里**才有效。

抓差分序列时四条硬纪律：

- **oracle 有状态**（对象在它堆上分配、宿主保存这些指针）→ 必须同时记录**返回值**，否则第二条调用就没法把指针翻译成自己实现的指针。
- **一条真实调用序列就是回归语料**：比「实机再点一遍」便宜一个数量级，还能把崩溃离线复现到第几条调用。
- **比首个分歧，不是一致率**：99% 一致而第一条错，后面全是垃圾。
- **报定位，不只报计数**：序列类比对一次给出「长度差 + 首个分歧下标 + 该下标两侧取值」。只给 `mismatches=N` 等于把定位留给下一个人；**长度差往往直接点名缺的是哪个元素**（`bodies COUNT a=45 b=44` 比后面 26 条逐项差更快指向「少一个 body」）。

选题时反过来用：**先问「这个结论能不能由被测系统自己写出来」**——能写的话，整条仪器链都可以省掉。

## 3. 置信度分级

同一套流程对不同问题给出的确信度不同。报结论前先标**尺度**，再谈**多高**——同一对实现完全可能「返回值全同、波形全同、字节不同」。

| 尺度 | 可信度 | 成立条件 |
|---|---|---|
| 崩没崩 / ABI 对不对 | 高（可证伪） | 有**能产生反例的入口**：探针、抓包、把原二进制加载起来。读代码不产生反例 |
| 调用序 / 返回值 | 高（可证伪） | **口径固定**：比的是调用序列；指针返回值要先扣掉地板 |
| 状态数值 | 中（可量化） | 连**容差**和**首个分歧**（step / 字段 / 双方取值）一起报；只报一致率等于把信息扔掉 |
| 输出（波形 / 画面 / 字节） | 低（只能逼近） | 分窗比，不报整段均值；必须说明它**不等于内部逐位** |

- 「崩没崩 / ABI」一次反例就能定死，所以最先花钱的是**入口**，不是读代码。
- 「调用序 / 返回值」只在口径固定时成立：**计数与幅度、整段与分窗会给出相反结论**。
- 「输出一致」不可证：`corr=0.9999` 说的是「混音后波形重合」，中间隔着共享模式重采样——没证明的是哪一层，要写出来。

**桩 / 替身的分级**：桩 harness 返回 plausible 常量只证明**入口齐备**，档次是 `L2-A`（ABI 层），不得升格为行为等价。

## 4. 覆盖边界写法模板

用法里直接抄：

```
覆盖：<函数/字段/事件的集合>；判据：<PASS 条件>（比对类再加：长度差 / 首个分歧下标 / 两侧取值）
边界：看不见 <列表>（原因：<静态导入才有 / 需要符号 / 采样间隔>）；
      地板：A/A <数字>（<输入>、<oracle>、<次数>）；量化步长 <数值/规则>（记录精度）
失效：<上游版本> 变更后重跑 <自检命令>
```

## 5. 控制面失效时：改持久化状态，不改命令通道

当自动化接口的写操作静默失效（I18），**找这个组件的持久化状态文件**——命令拼法再复杂也救不了失效的通道：

- 断点/书签/注释 → 调试器的模块库文件。
- 配置/布局 → 组件的 ini/JSON。
- 会话状态 → 存档/缓存。

判据：**离线写入 → 重启组件 → 用只读接口确认它按新状态运行**。这条路可版本化、可审查、一次写几十条；坏处是写错时组件可能不认——先备份原文件，先用 1 条做最小验证。

配套纪律：命中后用「记录并继续」的模式（写日志 + 自动继续）——一次人工操作变成整段对象序列；「停止型断点 + 逐次读内存」把每次命中都变成一次人工注意力和一次往返。
