# 冻结与交接（换目标前）

收口后要换下一个目标 / 项目时，冻结是**一次动作**，不是「代码留在原地不再改」。目标是让旧树能独立复跑、新树不再被旧门禁拖住。

## 步骤

1. **先跑门禁，再搬**。把当树验收套件（整机 gate、A/A 地板、函数 A/B、宿主回归）跑一遍；结果 JSON 收进冻结树的 `docs/freeze-gate/`，冻结 fact 记数值、提交号、日期。搬完在**新位置重建并原地复跑同一门禁**——两次都绿才算冻结成立；重建会暴露构建系统 / 相对路径 / 默认产物路径里的隐藏假设。
2. **整棵目录一起搬**。工具的根目录通常由脚本位置推出；只搬 `tools/` 不搬 `work/`、`build/`、`mapping/`、`docs/`、oracle，会让所有默认路径指空。把 oracle 与共用库的**运行副本**放进冻结树（记 md5），根目录只留共享原件；gitignored 的 `work/` / `build/` 用重命名搬（同卷瞬时），不要复制几十 GB。
3. **默认产物路径也要冻结**。默认宿主 / 默认 exe / 默认 build 目录必须指向**当前**构建；旧构建目录是负面对照，不能当默认值——否则「冻结后复跑」会静默跑在旧产物上。
4. **冻结树自带规则与证据**。把项目 `AGENTS.md` / `docs/agents/face-spaghetti.md` / `README.md` 移入冻结树，写冻结日期、基线提交、复跑命令、已知限制；根目录写新的活动规则；冻结 fact 在活动台账续号（不要新开一套 id）。历史 fact 里的绝对路径加一句「指冻结前布局」，不改台账。
5. **活动树不依赖冻结树**。新目标的仪器 / 宿主 / 台账不 import 冻结目录；冻结门禁不进入新目标的验收。冻结后冻结树只读：发现缺陷 → 活动台账记 fact + backlog 开条目，除非用户明确解冻，不在冻结树里动手。

## 完成判据

- 冻结前后两次同一门禁都绿，且第二次在**搬迁后的新位置**重建并原地复跑；
- 冻结 fact 有数值、提交号、日期与复跑命令；
- 活动树没有对冻结目录的 import / 路径依赖；
- 冻结树只读，后续缺陷只进活动台账与 backlog。
