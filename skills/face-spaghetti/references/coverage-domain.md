# 判据定义域表

（仓库级的领域文档是 `docs/agents/domain.md`，管 glossary / ADR；本表是覆盖类任务的判据定义域，两者不是一个东西。）

**先声明完备性，再测。** 测试全绿只说明「仪器撞到的点」通过；没声明定义域时，缺的东西是无限的——你只能发现碰巧撞到的东西，只修撞到的三个点，第四个必然出现。完备性靠**枚举**，不靠测量。

行为等价 / 覆盖类任务在**开工与收口**各交一份表。落点用项目约定（默认 `docs/coverage-domain.md`，或 plan 旁），**不进台账**（`SKILL.md` §8）。

## 枚举：从代码与数据列，不从仪器列

先按模块 / 接口边界划子系统（窗口、渲染、物理、输入、状态机、存储、音频……），再对每个子系统答：**它的行为由哪些量决定？** 枚举来源至少过一遍：

- 接口 / 导出清单（导出表、ABI 表）：每个入口一行；
- 数据结构字段：每个参与行为的字段一行；
- 调用点与分支：状态机的每个状态 / 转移、每个回调入口；**消息表按「消息 × 门控前置 × 入口」枚举 cell**——一条消息可能先命中提前门而没执行 dispatch 分支，同一 case 也可能由消息、控件菜单、加速键多个入口到达；
- 数据文件 schema：配置键、场景参数、资源清单；
- **目标面（二进制资源与导入表）**：复刻 exe / 安装包时，PE 资源本身就是行为清单——`RT_MANIFEST`（依赖 `Microsoft.Windows.Common-Controls 6.0` ⇒ 宿主必须带同款 manifest，否则对话框没有视觉样式）、`RT_CURSOR` / `RT_GROUP_CURSOR`、`RT_DIALOG`、`RT_STRING`、版本块；导入表每一项都是一个待判定的外部依赖；
- 常量与参数表：力律、阻尼、阈值、尺寸 / 周期表；
- **开关型决定量**：每个选项 / 模式（`quick`、`messages`、动画、测试模式、语言、输入通道）的**每个取值**都是一条 lane；不允许把 `quick=0/1` 合成一行。**程序默认值那条 lane 必测**——用户不设置任何选项时走的就是它。
- 输入通道与时间：输入事件、`dt`、迭代次数。

**反模式：拿「现有测试 / 仪器覆盖了什么」当定义域。** 那是仪器的视野，不是被测系统的定义域；用它会把表做成自我实现——表永远刚好等于已有判据。

**目标面漏项是典型缺口**：资源里有的东西没人读代码时想到，就永远不进表。开工前跑一次目标面清单，每条资源 / 导入项给归宿（`measured`，或 `unmeasured` + 回流条件）。

## 表

| 子系统 | 决定行为的量（枚举） | 来源（代码 / 数据） | 状态 | 判据 / 仪器 | 缺口与回流条件 |
|---|---|---|---|---|---|
| 例：力场 | 力律、施力点、阻尼、dt、迭代数 | `F0xx`、`src/…:行` | `measured` | `step_ab` 787 步 | — |
| 例：可见性 | 显示 / 隐藏命令、alpha、活动集合 | `F0xx`、脚本调用点 | `unmeasured` | — | 缺触发路径；回流见 backlog |

状态三种，**禁止留白**：

- `measured`：有仪器判据 + 正例 + 必 FAIL 的负例 + 地板；行内引台账 fact 与命令。
- `unmeasured`：量已枚举、位置已定位，但**没有判据**——未覆盖项的默认值。
- `unknown`：连量都没定位（只有现象 / 反编译候选）；写明还缺哪次观测或哪段代码。

**未覆盖默认 `unmeasured`，不是 `PASS`。** 「测试全绿」「通过 N/N」只是 `measured` 子集的成绩。

**标记 vs 状态**：`STUB(UNMEASURED)` 是代码 / spec 里给桥的标记（大写），`unmeasured` 是表里的状态值；桥行固定 `unmeasured`，缺口列写 `bridge`（`claims.md` 依赖桥）。

## 完备性检查（收口前跑）

1. **正向**：表里每一行都能指到代码 / 数据的出处；指不到 → `unknown`。
2. **反向（清单减法）**：代码 / 数据清单里的每个决定量，在表里至少一行。按导出表、字段列表、配置键、状态枚举逐项对账；对不上的补行。
3. **无空行**：任何「待定 / 可能 / 大概」都改成 `unmeasured` 或 `unknown`。
4. **仪器映射**：把现有仪器 / 测试逐条映射到表行；映射不到的行就是覆盖缺口。
5. **plan 引用**：验收条目引用表行；表随代码变化更新（旧行置 `过期`，新量补行）。
6. **lane 覆盖**：每个开关型决定量的每个取值都有一行/一条 lane，且至少一条判据级录制；缺哪条 lane，该行只能 `unmeasured`。判据的录制固定了开关值时，**另一侧的功能等于没测**——事件流/状态/像素检查点都在同一条 lane 上。
7. **cell 粒度**：cell 是「可独立翻转的最小 lane」。转发 / 常量 / no-op 分支没有可观测差异，必须加 spy（参数 / 调用环 / 状态写）与必 FAIL 负例，否则只算 control-flow coverage，记 `unmeasured`；合并或拆分 cell 要留变更记录，否则分母可被随意缩水。

## 修法选择

- 「补三个测试」= 点的扩张：只覆盖撞到的点，结构没变，第四个必然出现。
- 「定义域表 + 按表补判据」= 集合的声明：先知道全集，再决定哪些必须 `measured`、哪些接受 `unmeasured` 并写回流条件。
