# H. 迭代速度

| 症状 | 机制 | 规则 |
|---|---|---|
| 「工具能出反编译，迭代就快了」 | 生成侧早已不是瓶颈 | 迭代速度 ≈ **一次探测砍掉几个假设**；乘数按 ROI 排：判据机器可判 > 内部状态可见 > 结论可重放 |
| 「得换个更硬的仪器才能继续」 | 仪器成本可能超过它要回答的问题 | 先算问题值不值；换尺度往往三行代码解决（屏幕定时采样 > 上调试器拿一个定时器参数） |
| 「上游开源了，可以直接抄」 | 开源只降低猜布局成本 | **不提供等价性**：先对导出名/序号，再逐函数比行为 |
| 「真实样本太复杂，先逆向它的谜题」 | 测试目标只需要某类对象/事件；真实样本是别人设计的谜题，逆向成本高且不可控 | 造**合成输入夹具**：容器 round-trip 逐字节 + oracle 加载 + 自选对象；同名替换现有 slot，不新增条目（instruments §0.8） |
| 「这段逻辑先写，测试以后补」/「这条路径没法测，但看起来对」/「跑通一次就算验证」 | 不可测 ⇒ 无判据 ⇒ 不可归因；`no-op` 语料、未隔离的颜色源、dead/blocked 函数都能产出全绿 | 实现以可测性为前置：`test id` + 判据命令 + 正例 + 必 FAIL 负例；指不出 → `blocked` + backlog 回流条件；已写但无判据的代码不计进度（SKILL §0） |
| 「B 测不了，所以 A 也别写了」/「先写个假 B 把 A 跑通，反正以后会换」 | 拒绝写会让 A 永久卡死——把 B 的不确定当成对 A 的禁令；静默假 B 会把 A 的绿灯变成假证据——A 只证明与 stub 一致，不证明 B | 显式桥：`STUB(UNMEASURED)` + 回流条件，fail-closed 或可配置；A 的结论只到 `partial` / `reacher-only` / `unmeasured`，不标 `已证`。六条见 `claims.md` 依赖桥 |
