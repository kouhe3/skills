# D. 布局与常量

| 症状 | 机制 | 规则 |
|---|---|---|
| 「EAX 是对象指针，肯定就是 Self」 | EAX 可能是普通第一参数、Lua C 的 `lua_State*`（在栈上）、或 `__stdcall` 的普通参数 | 先判调用约定，再看 `[eax+off]` 与调用点 `mov eax`；Pascal 方法才把 EAX 当 Self（对象头 `[Self]=VMT`，instruments §0.5） |
| 「函数出现在多个 VMT，类名不唯一」 | 继承：子类 VMT 复用同一个方法指针 | 沿 `VMT+8` 父链、同槽号比较，找到父 VMT 不再含该函数的层 = 定义类；运行时 `[Self]` 可能是子类（instruments §0.5） |
| 「反编译里偏移是 +28，照着写」 / 「字段地址从相邻全局猜，读出的 x=9 而布局中心是 296」 | 布局是 L1 级猜，猜错不报错、只产出可信但错误的对照表；命名全局（`cy`）要解析到真实地址，相邻地址常是别的结构 | `offsetof` 或「置值读回」实测：逐字段置值再读回；字段地址以反汇编**操作数符号**为准（`mov eax, cy` → 解析 `cy` 地址）；读出值先过值域/公式交叉核对（图标 x 应 ≈ (宽−32)/2） |
| 「常量在二进制里搜不到，说明原版没这个钳位」 | 钳位可能按 `dt` 归一化、运行时算（`0.5π/dt`），常量不在 `.rdata` | 改做**映射实验**：扫输入找饱和点，再变 `dt` 看饱和点是否移动——移动=每步量钳位，不动=常数钳位 |
| 「某字段恰好是 50π / 250 / 整千」 | 值 × `dt` 可能是漂亮数 | 先做一次乘除（-157.0796 × 0.01 = -0.5π ⇒ 每步最大旋转/平移的钳位特征值） |
| 「只测了孤立对象，可以下结论」 | 同一公式放在求解前/后，孤立场景结果相同，带交互才分开 | 受控实验要**同时覆盖孤立与带交互**两种场景 |
| 「两版产物行为不同，直接读反汇编」 | 有几项几十秒能验证的低成本项命中率最高 | 先按序排除：编译期常量折叠（`const` → `#define`）、池大小常量、默认构造是否清零、`/fp:` 开关、优化等级 |
| 「逐位只对上六成，模型肯定猜错了」 | 全链累积把「公式错」与「逐级量化/累计误差」混在一起，看不出该改哪一处 | 先做**单步递推**：拿 oracle 的中间值当输入，只预测下一个值（同一问题：全链 19/75 逐位命中，单步 59/64 ⇒ 公式对、差在精度与顺序）；再逐个变一个维度——输入/角度的存储精度、中间累加器类型、求和结合顺序、三角/数学实现、乘法顺序 |
| 「参数都换过了，还是差 1 ulp」 | 1 ulp 可能已经是 oracle 的存储精度，不是缺陷 | 先量量化步长（float32 在 `\|p\|≈18` 时 ulp=1.9e-6）；容差低于步长时判据没有意义（instruments I21） |
| 「同一个键的多个样本数值不一致，说明有多个变体」 | 结构里可能有**恒变字段**（未初始化/栈残渣，例：circle def 的第 4 个 float 每次不同）；也可能是聚合口径没自证 | 聚合前先做**同键逐位一致**检查：先排掉恒变字段再比；排掉后仍不同才承认是多变体（生成器口径见 instruments §0.1） |
| 「先跑通，签名/布局以后再核对」 | 错误 ABI 不一定崩：多余参数被 cdecl 调用方清理、静默忽略，写坏的是对象头部，症状延迟到无关调用 | 未知签名用「逐字节/逐参数置 1 + 最小可崩调用」定槽位，再用反汇编确认；「跑通一次」不算签名正确（实例：GetFilter 参数顺序反了，6 字节写进 shape 头，几步后 ReFilter 崩在 0x8） |
| 「反编译的算式和常数都对，运行值差一个量级」 | 乘除对象/角色可能读反：`min(315,30·d)` 与 `min(315/d,30)` 的常数、路径、调用链都一样 | 用 oracle 的一次真实调用记输入/输出，先定公式的方向与幅度，再写 claim；静态算式只给候选（SKILL §2.2） |
| 「trampoline 按 5 字节截断就行；寄存器 ABI 用普通 C 函数转发」 | `copy_len` 落在指令中间会生成坏跳板；C prologue 会改写寄存器入参；症状是无响应或崩溃，不是函数差 | trampoline 长度按指令边界解码；寄存器 ABI 用裸 `jmp [stub]` 转发；新增/改 ABI 通道后先用已知输入做 A/A + 正例自证，再用于判据 |
| 「`ab_call4` 调 1 参函数，进程直接 AV」 | 调用桥依赖被调方 `ret 4N` 自清栈；1 参函数只清 4 B，余下 12 B 让尾部 pop/ret 错位 | 按函数 `argc` 分派调用形状，其它 argc fail-closed；崩溃先判仪器 ABI，不先改被测函数（instruments §0.9） |
| 「回归里两个函数的 A/B 卡在第一个 `ab`，HEAD 也一样」 | naked 桥对被调方 `ret`（无栈参数）多 push 一个参数且不清理 → epilogue 用 saved ebp 返回；`cdecl` 侧没按调用约定分派 | 调用桥按被调方 `ret N` 配平；寄存器 ABI 用不 push 参数的那支；`cdecl` 走类型化调用（instruments §0.9） |
| 「prologue 扫描器拒绝了一个合法函数 / 放过一个坏字节」 | 字节扫描不是解码器：`6A ib` / `6B /r ib` 的立即数可落在 `0x70–0x7F`，被当成短跳转 | 扫描器按指令长度跳过立即数（至少 `6A/6B/68/B8–BF/83`），或改用真反汇编器 |
| 「按 Hex-Rays 的 `__userpurge` 签名传第 4 个参数，分支却走了默认」 | 函数 `ret 0xC` 只有 3 个栈参数；prologue 的 `push ebx/esi/edi` 之后 `[esp+0x18]` 指向第 3 个，Hex-Rays 的 `a4` 是错位 | 参数个数 / 槽位按 `ret N` 和 prologue 的全部 push 重算；用「只改一个参数、看分支 / 环」验证槽位；环长度不等先查参数错位 |
| 「合成 vtable 夹具一跑就 10 s 无响应，A/A 没有 mismatch」 | 夹具漏了被测函数里的一个 `call [obj+off]` 槽：该槽是 0，UI 线程直接跳 0；症状是**挂起**，不是断言失败，容易被误判成替身或被测函数的问题 | 跑之前从反汇编列出被测函数的全部 `call [reg+off]` / `call [imm]`，逐个映射到夹具字段并写 cb（清单进 case 注释）；超时先查夹具缺槽，再查死循环；环长度不等先查路由缺口 |
| 「按元素数实现 memcpy，A/B 首个分歧落在 +2 字节」 | 编译产物的失败回退可能用 `lstrlenW+1` 当**字节数**（`rep movsd` + `rep movsb`），反编译类型看起来像元素数；首版按 WCHAR 数写就多拷 2 字节 | 复制单位从 `rep movs*` 与计数来源（`lstrlen` / `shr ecx,2` / `and ecx,3` / `imul`）反推，别信反编译类型；目标先填哨兵字节，欠拷 / 多拷都从首个分歧偏移看出来 |
