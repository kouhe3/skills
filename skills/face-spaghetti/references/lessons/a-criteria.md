# A. 判据与口径

| 症状 | 机制 | 规则 |
|---|---|---|
| 「first-chance 日志里全是同一地址的 AV」 | 记录器把 `IsBadReadPtr/WritePtr/CodePtr` 内部的 SEH 探测也记成崩溃 | 按这三个函数入口 + `0x80` 过滤；过滤后正常启动 `EXC=0` 才算噪声地板清零；再合成一个被 `__try` 吞掉的 AV 作正例（instruments §0.4） |
| 「一条 fact 同时写机制和覆盖数」 | 机制结论与覆盖快照的定级/状态/自检钩子不同 | 拆两行：机制行 `已证（机制）`，覆盖行 `快照`（四条钩子）；混行会让 `快照` 掩盖机制结论（claims.md） |
| 「append-only 检查显示通过」 | 脚本只比较暂存区；工作区改动未入索引时是空比较；默认 glob 还漏 `*.MD` | 未暂存时退出 2（不静默通过），或显式 `--worktree`；默认 glob 同时含 `*.md`/`*.MD`；用临时仓库跑「未暂存 / 未跟踪 / 大写 / 工作树 / 合法追加 / 删 fact」六例自证 |
| 「一致率 99%，剩下算噪声」 | 均值/计数掩盖第一条错 | 只认**首个分歧**（step / 字段 / 双方取值）；后面全是垃圾 |
| 「整段相关 0.96，说明有差异」 | 整段均值掩盖分段 | 口径是**分窗 + 每窗最佳 lag**；只报整段等于误报 |
| 「超差个数涨了，说明在发散」 | 个数随场景活动量变化 | 归一化成幅度（`\|Δ\|/容差`）再看十分位；个数与幅度会给出相反结论 |
| 「波形 corr=0.9999，等于逐位一致」 | 中间隔着共享模式重采样与混音 | 输出重合 ≠ 内部逐位；写清「没证明的是哪一层」 |
| 「所有用例全绿，说明对齐了」 | 覆盖度 ≠ 等价性 | 逐例看 A/A 地板与首个分歧；最难的边界用例才是全部价值 |
| 「同一份日志 A/A=0，换独立录制就有差」 / 「同一关卡帧对不上」 | 同一份日志只证明解析确定；同一关卡 ≠ 同一瞬时态（动画/悬停/电机） | A/A 用**两次独立采集**；先钉时刻/输入/状态字段；静态 draw 与动态 draw 分开报，动态项单独给地板 |
| 「点击后立刻抓的同一状态，两次强制重绘差 5 万 px」 / 「判据时绿时红，重跑就好」 | 抓取不是状态：交互（点击/悬停/菜单）后窗口还有 pending 重绘，`settle`=无定时器也不等于 paint 已完成；单次抓取没有地板 | 交互 → settle → **连续两次抓取逐位一致才采信**（`stable_grab`），不一致就重试并报 `grab_unstable`；把「第几次才稳定」写进出处（instruments §2） |
| 「bbox 对上了，说明画得一样」 | 判据只比外接框：旋转的四边形与它的轴对齐外接矩形同分；90° 旋转、朝向翻转也看不出来 | 几何判据写清比的是 **bbox / 顶点 / 边方向**；要判旋转就比顶点或至少比第一条边的方向，否则把旋转态单列；负例要含 bbox 不变的扰动（90° 旋转/朝向翻转）（实例：手工轴对齐 + bbox 尺寸也能过全部用例） |
| 「全量 A/B 应该 52/52 零差，怎么有 3 关差」 | 一侧是桩、一侧已实现真实返回值；由返回值派生的实参（坐标、锚点）必然不同 | 先对齐两侧**实现级别**：桩对桩、实现对实现；否则只比调用序/非派生参数，把派生差异单列（实例：派生坐标 0 vs 9.09、锚点 0 vs 2.8） |
| 「从 oracle 标定相机/父图偏移，取第一个同名对象就行」 | 同名素材可能来自多个对象（撞名），首个匹配会被带偏；屏幕层/世界层/chalk 层偏移不同 | 同类对象**投票**或按层分组；单个匹配只作候选；标定值写进出处/快照，换关卡要重标（实例：同名对象撞名把 root 偏移带成 (0,-4)） |
| 「两个实现互相比对就够了」 | 双后端互比是循环论证 | 判据必须对**原版/oracle**，容差写进语料 |
| 「数字看起来合理，但系统性偏低」 | 快照基线取在动作**之后**（等它稳定再取），漏掉被测段 | 基线取在动作**之前**；每单元 `delta>0` 自检（实例：集合 649 → 187） |
| 「全量跑完才发现基线取错了」 | 一轮全量的成本高，错误要等表出来才看见 | 先 3 个单元验证产出形状（非空且随单元变化、timeout 内落地、基线在动作之前）；实例：3 关 30 s 挡住了 52 关 9 min 的一轮错基线 |
| 「脚本点到第二关就不动了」 | 「进关」判据绑定了某一关的画面模板，换一关就判不出 | 用**结构条件**（离开上一屏 / 出现某资产），不用单关外观；状态机对每个转移给 timeout 与恢复分支 |
| 「自动进关跑到第 N 关后全部停在 MENU」 | 活动存档的解锁进度字段截断关卡列表；不是探针/坐标问题 | 先读活动存档的进度与最大 index；临时解锁整文件备份，批次后恢复并核对指纹；一单元一进程把失败缩到单单元（instruments §0.2） |
| 「hit=0，说明这个函数没被调用」 | 仪器只数直接 `call rel32`；Lua VM 闭包、虚表、函数指针调用全看不见 | 全量前先放**阳性对照**（≥3 个必然执行的入口：脚本 cfunc / 每帧回调 / 启动路径）；全 0 先修仪器。实例：144 个 Lua cfunc 在调用点普查里全 0，而其中 122 个被脚本调用；入口探针实测 94/144 在跑 |
| 「启动时肯定跑过，怎么会是 0」 | 基线取在动作之前，启动/退出落在窗口外 | 0 只代表**窗口内**未观测；要支持「从未执行」，用覆盖启动→退出的入口级仪器，并把窗口写进快照 |
| 「649/1012 覆盖，和 166/361 命中，哪个对」 | 调用点与函数入口是两个观测单位 | 快照/表格标单位；跨单位不比较（instruments I23） |
| 「微基准 3×，整条链路肯定能快」 | 片段耗时 ≠ 链路瓶颈；热路径常被 I/O、日志、环境变量查询污染 | 先 profile 整链路再改；性能判据 = 输出逐字段不变 **且** wall 下降。实例：digest 微基准 3×，整链路只 +7%；真凶是每 8 条调用写一次进度文件（占 28%） |
| 「14 路并行，wall 至少减半」 | 算术下界假设 CPU 是唯一资源；超订、SMT、磁盘/内存带宽都会反向 | 并发度先实测一档，报告 wall **与总工作量**（实例：14 路 34.7 min vs 8 路 17 min，总工作量 3.6×） |
| 「文档/注释说门禁已经比较了地板」 | 注释是意图，不是实现；文档会漂移 | 判据以**可执行代码 + 实跑输出**为准；文档与代码冲突，先修文档再谈结论（实例：docstring 声称比 A/A 地板，代码只判 verdict） |
| 「日志里没出现 = 宿主没调用」 | 采集层可能有过滤表（只读 getter 可占日志 ~60%，默认丢弃） | 0 先分桶：仪器主动不记 / 语料没走到 / 窗口没覆盖；被过滤的换开关另录，或造合成契约探针（instruments §0.3） |
| 「改一行文档也要先预注册 fact」 | 把探测闸门套到了非探测任务上 | 纯文档 / 注释 / 计划整理直接改，不预注册、不占 fact；只有改判据、仪器或事实才走四步（SKILL §0） |
| 「装了入口桩，日志也报 installed=N，启动期却全 0」 | 代理/探针在 `work/` 里的副本是旧构建，缺后续新增的开关；日志只证明 patch 成功，不证明挂载窗口 | 仪器先过**版本门**：比特征串/md5 与当前 `build/` 产物；阳性对照同时放启动期与稳态（instruments I31） |
| 「两次独立覆盖跑，hit 集合差 1 个函数」 | 单次回调的调用时机抖动；覆盖 A/A 不是集合相等 | 算**对称差**并命名差集函数；地板 ≤1 可接受，>1 先修窗口；差集成员不进稳定覆盖（claims 普查） |
| 「numstat 出现 1 行删除，台账被重写了」 / 「提交前 `git diff --stat` 显示整个文件几万行改动」 | 行内状态流转/划删除线本来就是同数目 `-/+`；整文件重写的特征是 id 集合丢失或成片对称删除；脚本用文本模式写 CRLF 文件会把整文件翻成 LF（反之亦然），内容没变但 diff 是全文件 | 以 `append-only-check` 的 fact id 集合为准；新增行 `N 0`，状态更新看 id 集合不变；脚本改文件用 `read_bytes`/`write_bytes`，改完立刻看 numstat，整文件改动 = 行尾翻转，用 bytes 复原后再提交（SKILL §8） |
| 「验收阈值 0.65，夹具 0.6 就触发完成，记录最小 0.597」 | 夹具在完成阈值处执行完成动作，记录指标被夹具阈值截断；验收阈值等于夹具阈值时判据同义反复，贴线还会 flake | 完成阈值与验收阈值分开：验收严格高于夹具，关系写进用法（instruments §0.8） |
| 「扫了一小段内存没变化，所以那个状态不存在」 | 无变化只证明扫描范围/对象里没有可观测差异；UI 可能预创建、切换可见性/alpha/动画计数，或在别的对象里 | 报「无变化」必须带扫描范围；先枚举对象/列表/可见性/alpha/计数，再下结论 |
| 「静态场景全绿，剩下的 mismatch 全是几何」 | 剩余是 alpha / 灯态 / 气泡等**显示状态**，不是几何；状态由逻辑 / 脚本改，静态模型没有它的输入 | 静态几何与状态分账：先判 bbox / UV = 0，再把 alpha / 可见性 / 状态项单列；状态项要状态机或 oracle 状态读回（instruments §0.6） |
| 「同素材多实例位置差一截，公式错了」 | A/B 按同素材的**出现顺序**配对；引擎绘制顺序与模型调用序不同，顺序差被报成位置差 | 同素材多实例按**最近位置 / 投票**配对；几何集合相等后把绘制顺序单列 |
| 「实机 A/B 发现差异，用户说先记录不修」 | 现象是 L4，机制未归因；直接改代码会把现象当机制并扩大范围 | 现象写 `已证（现象）` + backlog 待修行，机制 claim 另起一行 `待证`；没有指令不动生产代码（SKILL §7 第 3 条） |
| 「补了三个测试就收口，随后又冒出第四个」 | 定义域未声明：测试只覆盖碰巧撞到的点，结构不变就永远有下一个 | 先交判据定义域表：从代码/数据枚举决定量，逐项 `measured` / `unmeasured` / `unknown`；未测默认 `unmeasured`，完备性用清单减法（coverage-domain.md） |
| 「旧 note 写的是取最右，和我测到的索引 0 对不上，先把旧说法写进下一轮」 | 旧 note / 反编译注释是 L1 措辞，被当成事实转抄；同一 claim 里的 L4 观测没参与对账，错误措辞又进下一轮简报 | 引用旧结论前先做「结论 vs 观测」对账；静态措辞与观测冲突以观测为准，先重读代码；观测值写进同一行，冲突未解释前不转抄 |
| 「实现里只有这几条分支 / 只剩 no-op 例，全绿，可以算对齐」 | 语料从实现的分支假设生成，且只覆盖 `no-op` / 早退；实现缺的路径与函数目的路径都不在语料里，全绿只证明实现与它在自己选的路径上一致 | 语料从**代码侧**枚举分支、调用点与状态转移；对齐四件：spec + 单元 A/B + fact + **目的路径语料**（每个目的路径至少一条真实例）；`no-op` / 早退只作边界；改分支后重跑该函数的正/负例。`A/A=0` 与逐例 `mismatch=0` 只证确定性与该语料内一致；自指（源 == 目标）、同参、`no-op` 用例不计入目的路径；部分通过不按比例升格 |
| 「首个分歧在 prep 的句柄/颜色调用里，说明函数少了一个分支」 | 每个 pass 的 setup/prep 没有完全恢复 live（缓存、句柄、颜色表、注入视图），prep 自己就不一致；采集环 / 句柄表容量不足时溢出截断或回落 sentinel，同样伪装成函数分歧；把 prep 差当函数差会去改已对齐的函数 | 函数 A/B 先看 prep：每 pass 的 prep 摘要（状态 + 句柄 + 采样表 + 注入视图）必须相等，prep 不等不出函数结论；首个分歧的区间起点由 prep 边界标出；采集环与句柄表的容量、溢出 / 回落计数进判据，报「第 N 次调用」先核对 N ≤ 容量；修仪器后重跑既有回归；仪器缺陷单独一行，不混进函数 fact |
| 「顶层字段计数是 0，所以这个函数不画；状态 CRC 直接写进报告当可复现值」 | 顶层字段常是第一个 case 或单例样本，不是聚合；CRC 含 raw scratch、屏幕坐标或进程句柄，跨进程 run-specific | 报告只引聚合字段并标口径（first case / per-case / aggregate）；run-specific 值不进判据，判据用同进程 A/A + 逐字段比较；跨进程只比稳定字段并写明排除了哪些 |
| 「plan 与图表的派生数字对不上，总数一样，应该没事」/「plan 头部的 gate 行是上一轮的，先不管」 | 派生数字手抄进 plan / 报告，分类和与总数没重算；笔误被总数掩盖，文字与可生成源分叉；头部 gate 行不会自动跟随台账，过期值被当成当前状态 | 收口按**可生成源**逐处对账（清单、历史、图表、计划头部 gate / next、backlog 缺口清单）并重算「分类和 = 总数」；头部 gate 行按最新台账改写；差异追加勘误，不手抄派生数字 |
| 「context 里已注入状态，实现却从种子数据取」/「单函数 A/B 全绿，组合路径仍差一个对象」 | 同一逻辑状态有多份物理副本（绘制缓冲、布局内嵌副本、视图），只 patch 一份时另一份仍是旧值；单函数 A/B 把两份种成一致，组合时才暴露旧副本 | 注入状态前枚举该状态的所有读写视图，逐视图写并读回；组合层在子函数入口 / 绘制点同时记录 live 与子函数实际 ctx 的副本，先证明副本相等再谈调用顺序 |
| 「plan 里的依赖句照它排 batch」 | 依赖句从旧 L1 note 抄来，不是从当前反汇编的 callee 清单派生；错误依赖把可做函数标 `blocked`、把顺序排错 | 每批开工前从反汇编重新派生 blocked 依赖（逐函数 call 清单）；plan 依赖句默认 L1；与本次清单不一致就追加 plan 变更并重排，不改历史行 |
| 「三 pass 都调真实的一次性 API，A/B 就能覆盖真实语义」 | 一次性 API 在同一进程只有第一次成功，后续 pass 返回「已存在」；canned 返回让 A/B 能比字段，但真实语义仍未测 | A/B 用 canned + 独立 integration；真实 API 只作 integration，不替代 A/B；替换 canned 前函数只到 `partial`（instruments §0.9） |
| 「负例靠上一条 case 的记录才检出」 | 采集环只在 `pn>0` 时写入，`pn==0` 沿用 stale 行；复位后负例可能掉检出 | 每 pass 先 `memset` 再快照；负例在复位后重跑，stale 环上的「检出」不算证据（instruments §0.9） |
| 「负例 0 mismatch，但 bad 样本只差一个返回值」 | 比较面漏了 `EndDialog` 的 nResult / 次数 / 控件树；一个两边都不读的 ctx 字段是假测试 | 返回值、次数、序列、控件树都进比较面；两边都不读的字段单列「未比较」，不算通过（instruments §0.9） |
| 「跨模块字符串指针不同，判不一致」/「调用环只差一个指针参数，其余全同」 | exe 与 dll 的 `.rdata` 地址不可比；实际资源 / 句柄相同 | 资源 id 原样、字符串按内容哈希；调用环里的指针参数归一化成 token、内容另存文本；给 S 加导出返回缓冲地址，别猜地址（instruments §0.9） |
| 「同一对象在两个 pass 里句柄号不同，说明实现有别」 | 裸句柄是复用值、无语义；按出现顺序编号时跨 case 回收会换号，`SelectObject` 返回的又是「先前对象」 | 按身份来源归一化（所属窗口 / stock id / pass 内创建序号），未知 raw 用带计数的 fallback 并逐 pass 复位；创建类与 `SelectObject` 只比成功 / 失败 |
