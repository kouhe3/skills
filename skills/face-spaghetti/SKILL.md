# Face Spaghetti

范围已知时计划先于事实；来源不可信时**事实先于计划**。本 skill 管后者：先判这个任务现在能不能开工，判完再谈怎么写、怎么记。

**核心断言**：每段代码落进四条**归宿**之一——进台账、进 plan、升成 `tools/` 下的仪器、进垃圾桶。四者之外的代码是借债。

> **开工前 60 秒**：先读本 skill，再碰生产代码。第一条动作是在台账落一行 `待证`（假设 + 互斥预测 + 机器判据），不是改代码；漏预注册的补救见 §2.1。

**可移植**：本 skill 只写相对约定与判据；项目落点与本机事实写目标仓库的 `docs/agents/face-spaghetti.md`（§9 的 setup 生成）。同族配置（issue tracker / triage 标签 / 领域文档）也在 `docs/agents/`，由 `/setup-matt-pocock-skills` 写。

**入口**：命中本 skill 触发词时（反编译产物 / 遗留二进制 / 无文档 SDK / 只能靠踩坑推进），入口是本 skill，不是 `mattpocock/skills` 的主流程（`grill-with-docs` → `to-spec` → `to-tickets` → `implement`）。依赖上本 skill 也在前段：那套流程假设用户能回答、代码可读、模块边界已知；屎山把这三个前提都打破。那套 skill 的三种取证方式里，`/prototype`（先做后定）与 `/research`（一手资料）可以在循环内用；`/grilling` 只取用户拥有的决定。屎山缺的是事实，不是决定；把事实缺口丢进 grilling，只会问出用户和文档都没记载的事。

| 问题 | 谁答 | 动作 |
|---|---|---|
| 范围 / 优先级 / 验收口径 / 取舍 / 命名偏好 | 用户 | 可以 grill；一轮问完 frontier |
| 行为 / 格式 / 调用约定 / 状态迁移 / 分支覆盖 / 布局 | 被测物 | claim → probe / prototype；**不问用户** |
| 第三方平台 / SDK / 协议语义 | 一手文档 / 源码 | `research` 或直接读；按 §4 定级 |
| 只有用户能看到的运行时现象 | 用户 | human lane；仍要机器捕获 |

用户对机制问题答「不知道」不是阻塞：转 `待证` + 探针；探针也造不出才 `blocked` + 回流条件。分工、四本账与逐 skill 边界见 `references/pairing.md`。

## 0. 闸门：先判，再写

先按任务形态分流；命中一行就执行该行动作，再进三态判定：

| 任务形态 | 动作 |
|---|---|
| 纯文档 / 注释 / 计划整理 | 直接改；不预注册、不占 fact |
| 只是查资料 | 直接查；结论要落账时再按 §2 |
| 想先 grill / wayfinder / 写 spec 再开工 | 先过本 skill 入口：只把范围 / 取舍交给 grilling；行为 / 格式 / 覆盖类问题转 `待证` + 探针或原型（`references/pairing.md`） |
| bug 稳定可复现 | 先复现再改；复现命令进台账 |
| GUI 输入自动化 / 拖拽验证 | 先造**状态回读 + 坐标标定图**；标定 claim 过闸后再写行为判据（`references/instruments.md` §0.7） |
| 真人输入 / 目测 lane（`needs` 含 click / visual / desktop） | 先过 **human-lane 预检**：触发链实测 + 干净进程（替身不吞对话框）+ 坐标 / 证据 / 提示协议（`references/instruments.md` §0.7） |
| 造合成输入夹具 / 合成语料 | 先证容器可逆（round-trip 逐字节）+ oracle 能加载；夹具进测试目录，一次性生成器进 gitignored 探测目录（instruments §0.8） |
| 「手写语料全绿」但没跑过随机输入 | 先交**随机语料 lane**：判据与三条自检见 §5 |
| 新增 CLI 开关 / 资源 / 消息处理 | 先写 smoke：**一条正例 + 一条必失败负例**。参数解析差一个偏移就会让整条路径静默失效——「有开关」不等于「开关生效」 |
| 新增/改动**按开关分叉**的路径（选项 / 模式 / 动画 / 语言 / 输入通道） | 先交 **lane 表**：开关 × 每个取值 × 语料/判据，且必须含**程序默认值 lane**；缺 lane → 该 lane 记 `unmeasured`（`references/coverage-domain.md`） |
| 行为等价 / 覆盖类（「测试都过了」） | 先交**判据定义域表**；没有表判「改造后做」（`references/coverage-domain.md`） |
| 进度图 / 完成度分母（主分母饱和，或要决定什么算奖励） | 先交**双层分母**：清单分母 + 枚举 lane cell；奖励单列、不改主百分比（`references/progress.md`） |
| 宿主 vs oracle 比窗口 / 控件几何 | 比较基准落**客户区**与相对客户区的 rect；两侧环境差（菜单栏 / 边框 / DPI / 主题）归宿主特性，`window rect` 差 = NC 区、不作等式判据（I39）；缺失模板 / 资源先写提取脚本 + `--check` 幂等复刻 |
| 被测函数是进程入口（WinMain / DllMain / main）或只能跑一次 | 不走进程内二次调用；做**启动入口 A/B**：fresh process + 入口调用点替换 + 启动事件环 + `mark_end`；先跑 1 hook + 1 边界 spike（`references/instruments.md` §0.11） |
| 实现 / 复刻类（含已对齐函数的未覆盖路径） | 先过**可测性门**（下）；缺一 → 不实现，写 `blocked` + 回流条件 |
| 想并行 / 派子代理跑多条 lane | 先过**并行门**（§1）：观测面未冻结就串行；探针发明权留主会话 |
| 冻结 / 交接 / 换目标 | 先跑门禁把结果收进冻结树，再**整树搬迁 + 原地复建立跑**（`references/handoff.md`） |
| A 依赖 B，B 暂时不可测 | 走**依赖桥**：显式 `STUB(UNMEASURED)`，六条见 `references/claims.md`；A 的结论只到 `partial` / `reacher-only` |
| A 的合同是转发 B 的调用 / 返回值 | 走 **Wrapper 例外**：判调用环，B 的内容单列 `UNMEASURED`（`references/claims.md`） |
| 来源不可信 / 二值判据写不出 / 机制断言未证 / 靠踩坑推进 | 过下面的闸门 |

`来源不可信` 包括反编译产物、遗留二进制、无文档 SDK、只能靠观察行为的第三方实现。

**判据来源三分**：开工前先答「我拿什么当判据」，再选三态。三种对象的做法不同，混用会得出「全绿但没有价值」。

| 判据来源 | 怎么判 | 典型 |
|---|---|---|
| 有行为规范（协议文档、公开 SDK 文档） | 照规范断言；规范没写的行为留 `unmeasured` | 协议客户端（TL schema + 官方文档）、公开 API |
| 只有实现（源码或可执行物） | 差分 oracle：同一输入两侧逐字节比，只认首个分歧（§6） | 对现有实现的 RIIR / 复刻 |
| 都没有 | 记录行为 → claim → probe → 台账，断言只锁观测到的形态 | 反编译产物、闭源 SDK |

**来源是「只有实现」且上游在动 ⇒ 只有快照态，没有完成态**：判据不必降级，变的是分母——gate 行记 `status=snapshot` 与构建指纹，覆盖数用 §8 的 `快照` 行，不写「完成」。这类任务的收口是「本轮快照 + 已知缺口」，不是 100%。

**兼容面三层**：写 gate 前先写清承诺替换哪一层；三层判据互不替代。

| 层 | 对谁 | 判据 | 代价 |
|---|---|---|---|
| 协议 / 服务器 | 服务端 | 能登进同一服务端、能收发；两侧互操作 | 低，独立实现都做得到 |
| 本地存储 / 数据 | 既有实现的存量数据 | 读得懂旧格式、写回能被旧实现读 | 高，且绑上游版本（私有格式只有实现，没有 spec） |
| 二进制 ABI | 替换既有库 | 导出符号集齐全，同一 ABI 下输出逐字节相同 | 中，只覆盖 ABI 之上的表面 |

「替换 ABI」隐含**接管存量数据**：存量格式在 ABI 之下时，ABI 全绿也不等于用户能换。格式开源可读 ≠ 有 spec——权威是那份源码，随版本变，仍按上一段记快照。

**判据形态由输入的随机源决定**，不由对象类型决定。先答「这份输入里有哪些东西每次都不一样」，再选比什么：

| 形态 | 什么时候只能用 | 例子 |
|---|---|---|
| 逐字节 | 输入完全确定 | 固定文件对 dump、官方向量 |
| 字段 | 输入含随机段，但结构确定 | 加密包里的随机 padding |
| 不变式 | 算法本身含随机，值按设计不可复现 | msg_id 的低位随机，只剩 `%4==0`／严格递增／高位=时间 |
| 结构 | 随机段多到无法逐字节，且顺序也被打乱；分层结构本身确定 | TLS ClientHello：解析成 `(类型, 内容)` 后比扩展集合 + 归一化固定段 + 自洽校验（HMAC 覆盖整段） |
| 解码后等价 | 编码器的输出字节不可复现（压缩器、打包器），但解码结果是确定的 | gzip：比解压后的对象，不比压缩字节；两侧压缩器不同也不影响 |
| 判定 | 输出是「接受 / 拒绝 + 文案」，输入空间靠分支枚举 | DH 参数门：位数 / 模表 / 两层素性各给正反例，再补随机模数；库函数（如素性）用标准算法对齐，不复刻轮数 |
| 别名 | 输出是「另一个对象会不会跟着变」 | `clone` 共享 / `copy` 隔离 / 无 COW：**写一处、读两处**，只比 size 与内容看不出别名 |

**形态选错等于判据错**：拿「字段」去判一个随机算法，会得到两侧永不相等；拿「逐字节」去判含 padding 的包，会得到同一实现两次也不同。两者都会被读成「实现有 bug」。形态不是口味，要与输入的随机源一一对应；同一对象的不同路径可以落在不同形态上（参数门用「判定」，包装后的载荷用「解码后等价」）。

**造 oracle 的便宜路径**：对象是库代码、入口是 private 时，不改构建系统——写几十行探针，用同样的编译 flags 直接链接已构建的静态库（`--start-group … --end-group` 解循环依赖）。oracle 源码入库（`tools/fixtures/<name>.cpp`），完整构建命令写在文件头，基线值钉进 fixture。这样换机器能重放，门禁也不必每次重编 oracle；探针缺失时门禁报 `MISSING` 而不是静默跳过。**先看依赖是注进来的还是自己造的**：对象通过构造器接收协作对象、每次调用接收回调时，用「双假」直接驱动真实代码（假传输注入字节 + 记录回调收事件），比造一个引擎/服务器便宜一个数量级；`SessionConnection` 就是这样从 `blocked` 变成可判的。

开工前判一次，落三态之一，并写下一句理由：

| 判定 | 条件 | 下一步 |
|---|---|---|
| **直接做** | 关键前提有 L2+ 证据、判据是二值的（授权范围见 §4）、覆盖类已交定义域表、实现类已过可测性门 | 写验收标准 + plan |
| **改造后做** | 前提可证但未证，或判据不是二值的 | 列改造项（造 oracle / 提参 / 缩状态空间 / 换判据 / 切片），改完回到闸门 |
| **拒绝** | 没有 oracle 且无法构造，或答案只能靠主观判断 | 写明缺什么、要谁补、改造成本，并写进 `backlog.md` 带回流条件（§7 第 3 条） |

**可测性门（实现前硬检查）**：四件齐备才写代码——`test id`、一条机器判据命令、正例、**必 FAIL 的负例**。指不出 = 不可验证 = 不实现：落 `blocked` + backlog 回流条件，`blocked` 是合法交付。仪器同受此门：先自证（A/A、阳性对照、版本门），自证不过的仪器不判被测函数。副作用（modal / registry / 句柄 / 时序）无法隔离的路径按 `integration` / `blocked` 交付，判据口径保持原样。能测的函数按 **RED → GREEN** 落：先写断言、看到它失败，再写实现；实现后同一条断言转绿。

**负例的寿命**：必 FAIL 的负例只能架在**长期不存在差异**的点上。靠「实现还没写」制造差异的负例，实现正确后必然转绿，`failures=0` 与「实现正确」就此互斥——把该 case 转进正例组、另换一个未实现点；换不出来就用台账里记录在案的已知缺陷当负例，并在行内写明它是缺陷。放宽判据不算换。**已知差异全部修完时负例组就该清空**，改由管道自检接手（两侧指纹不同、正例输出非空、语料条数下限、零重复），台账写「当前无已知差异」——空负例组不是漏洞，伪造一条才是。管道自检只证明仪器跑得动，不证明判据抓得住错：每条新 lane 至少做一次**改实现不改判据**的变异（边界符号 `<`→`<=`、构造号末位），看到首个分歧行再恢复，证据记独立 `已证（现象）` 行，不冒充预注册。**变异后先确认构建成功**（rc=0、warning 数不变）再跑判据：编译失败时跑的还是旧产物，会得到假绿——假绿比红更贵。

**变异不红也是结论**：改实现后仍全绿，说明该分支在当前输入域下等价（护栏不可达、该形态不在表里、语料没覆盖它）——写进台账并给出**一条能区分它的输入**；分不出就记 `unmeasured`，不要当成「变异做过了」收尾。

「差不多能行」不算通过：理由必须指到具体前提或具体判据。判定落进 plan 头部：`gate: passed | mode=<直接做/改造后做/拒绝> | oracle=<…> | criteria=<命令> | round=<n> | status=<planned/running/blocked/done> | date=<YYYY-MM-DD>`；续轮只改 `round`/`status`，`oracle` 或 `criteria` 变了才重判。

**完成判据**：plan 头部有 gate 行；triage 命中的每一行都落了动作（直接做 / 改造项 / `blocked` + 回流条件）；新仓库先跑 §9 的 setup（写出 `docs/agents/face-spaghetti.md`）。

归因卡住时先过 `references/lessons.md` 的分诊表（七问），再按分区对号；只读命中分区。

## 1. 改造：把不可判改成可判

**五问**，逐条回答；否或写不出理由就先改造：多项式时间有解吗？状态空间有限吗？反馈几秒？判据直接吗？能切片并行吗？

**并行门（编排器只在冻结后有用）**：「能切片并行吗」问的不是工作量能否拆小，而是**观测面是否已冻结**——控制面命令 ABI、状态 digest / 像素基线、仪器四件事、lane 表、每 lane 的隔离命名空间（桌面 / 控制基 / 运行副本 / 注册表或配置覆盖）全部就绪，才允许把 lane 派给子代理。claim 形成（未知签名 / 布局 / 机制）与仪器 bootstrap 永远串行，由主会话持有；可派发的是**已冻结判据的 lane**。缺项时并行只产出互不兼容的探针与冲突 fact，应先把缺项做成仪器或改造项。编排职责与派发边界见 `references/difficulty.md` §8。

**派单的验收口径**：task 里写死「固定语料 + 禁止改语料 + 自证命令（如 `git diff --stat <语料目录>` 为空）+ 撞到判据自相矛盾就回报，不许改判据」。语料随实现推进而变，子代理无权改判据——否则它会用放宽判据的方式「达标」。

改造项：造 oracle / **提参** / 造**合成契约探针** / 造**合成输入夹具** / 造**状态回读 + 坐标标定图** / 缩状态空间 / 换判据 / 换尺度 / 切片并发 / 压反馈（无头 / 离线 / 子阶段化）。**提参**指先问被测函数从环境读了什么：读时钟 / 随机 / 网络的，最便宜的改造是把 `now`、随机源、IO 变成函数参数——`AuthData` 每个方法都收 `now`，脚本喂时间就能逐字节判；同一个模块里自己读 `Time::now()` 的 actor 才真的 `blocked`。「可判」与「blocked」的分界常在这里，不在对象类型。

语料有**结构盲区**（采集层过滤、宿主从未调用）时先造契约探针：固定序列点遍每个入口、两侧各跑一遍。它比补语料便宜，还能抓「跑通但 ABI 错」——录制只证明被观测到的调用（`references/instruments.md` §0.3）。

被测对象消费数据文件（关卡、脚本、录制、配置包）时，先造**合成输入夹具**：容器 round-trip 逐字节 + oracle 加载读回，对象与输入由你定（instruments §0.8）。

每问的判法、五项任务表、A–D 分级与选路：`references/difficulty.md`。

**完成判据**：五问逐条有答案；每个「否」都有对应改造项，或写明为什么只能 `blocked`。

## 2. 四步循环（改造后执行）

一轮探测 = 一次可落账的最小单元。四步走完才算一轮，台账必须多一行。

### 2.1 Claim

写**三行**：

1. **假设**：一句可判真假；置信度 高/中/低（定义见 `references/claims.md`）；错了最可能错在 ___。
2. **互斥预测**：成立 → ___；不成立 → ___；两者要能被同一命令区分。
3. **机器判据**：`<command>` → `PASS=<condition>`（含地板 / 容差 / 窗口）。

三行写齐才跑。假设来源限定为被测物 / 一手资料 / 已证 fact；用户口述只作线索（§4），机制问题不问用户——范围 / 取舍类例外（`references/pairing.md`）。三行可以边读 oracle 边成型（§2.2 的差分取证属于**形成 claim**）；**动生产代码之前**先往台账追加一行 `待证`（预注册：假设 + 判据）。Probe 结束只回写这一行；claim 在探测中改了，改这一行，不另起重复行。探测中派生的新 claim（先证入口、再证状态切换）另起一行 `待证`；同一 claim 的新证据只回写原行。

**探针不是预注册**：差分取证 / 一次性探针只属于形成 claim；探针跑完、动生产代码之前，仍先落 `待证` 行。事后补登要在行内注明——它无法证明判据在改代码前就存在。**探针文件也算被测实现的同批产物**：先写探针（或探针与实现同批写）、台账最后补，等于没有预注册；补救是「回退-重放」而不是只在行内写「事后补登」。判据：`git log` 里 `待证` 那一行所在提交早于或等于第一个探针文件所在的提交。

**已经改了代码才发现漏预注册**：不要只写「事后补登」。保留本轮补丁 → 回退本轮生产代码 → 先落 `待证` → 重放补丁 → 跑判据。只有回退-重放后的 `待证` 行才算预注册；最终 fact 按正常已证写，不写「事后补登」。

claim 是**普查**（覆盖表 / 通过数）、**性能 / 规模**或**仪器 / 输入仪器**时，三行各换一套写法；置信度分级与 `快照` 行同在 `references/claims.md`。

claim 与 plan 任务的术语用 `docs/agents/domain.md` 指向的 glossary 定义；改机制前读该区域的 ADR，与 ADR 冲突时显式写冲突，不静默覆盖（§9 领域文档，软依赖）。

**门**：这轮回答 plan 的哪一行（Open Question / 风险 / 写不出验收标准的任务）？**完成判据**：动生产代码之前，台账里已有预注册的 `待证` 行（假设 + 判据），且三行都能判真假。

### 2.2 Probe

| 约束 | 做法 |
|---|---|
| 标记 | 独立目录/命名空间 + 等价编译隔离（独立 asmdef / package / 入口）；文件名与提交前缀带 `probe` |
| 一次性 | 一条脚本：读 → 打印。状态放内存（持久化本身常是被测对象）；抽象、测试、错误处理全略。台账要引用的探针留档：升 `tools/`（带 `references/instruments.md` §0 的四件事），或留在 gitignored 的探测目录，并在台账行写**路径 + 生成命令 + 输入**。控制通道有长度上限时，大块输入走文件 token（instruments §0.9） |
| 只读正式路径 | 生产代码、共享配置、源数据只读；第三方 vendor 副本可改，每处标 `altered (Fxxx)` 并与 oracle 对拍；oracle 本体只读 |
| 共享资源 | 默认音频端点、系统混音器、用户存档/缓存/配置按生产数据处理：能隔离就隔离（独立 profile、私有桌面、虚拟音频设备），不能隔离就备份并在 `finally` 恢复；恢复命令写进台账。**同一共享资源的仪器不得并行**：串行跑，或用锁文件/租约（带死 pid 与超时回收，放 gitignored 目录）；并行只允许只读或资源不重叠。私有桌面只隔离窗口/输入：输入与观测在目标进程内，像素在桌面内抓（I29，`instruments.md` §0.7） |
| 环境干净 | 先清掉：单实例应用的旧进程、被独占的设备、上一轮残留进程，以及**脚本/自动驱动的启动开关**（固定点磁铁、自动拖拽一类）——**残留状态**与脚本驱动的症状和被测对象真有 bug 一模一样。**台账命令里的初始化参数也算环境**（开局 N 步的「初始化 + settle」）：省掉它，被测函数读到的 live 状态就不是判据假设的那个（I35） |
| 仪器版本 | 用当前 `build/` 产物：先比特征串/md5，阳性对照覆盖安装窗口两端（启动期 + 稳态），见 I31。**判据命令的默认目标也是仪器**：默认 `--host-exe` / 默认产物目录可能停在旧构建——台账写实际产物路径 + md5，构建目录变更后先跑一条「默认值指向当前产物」的自检 |
| 判据输出通道 | 子进程输出按**字节**收再宽松解码（`capture_output` 后 `decode(errors="replace")`）：被测物会把请求里的原始非法字节写进日志，`text=True` 会让仪器自己崩在 reader 线程、退出码却仍是 0。**报绿的同时打出 traceback / 解析异常 = 仪器部分失效，不是通过**。格式化本身就是第二个实现：双精度打 64 位位型，跨端比文本前先归一化换行与 locale（C++ `printf` 的 `\r\n` vs Rust 的 `\n` 就足以造出假分歧） |
| 控制面开关 | 改了启动模式 / 权限 / 发行开关后，先跑**通道自检**：无参、显式参数、环境变量、test 标志四个入口各一条，记录「有没有控制面」；**无参入口必须没有**，同时作为「永远开通道」这条过度修正的必失败负例。开关吞掉通道时，所有驱动该进程的仪器一起变红，症状是「连不上」而不是断言失败（I38） |
| 一次一个变量 | 一轮只变一个变量，结论才归因得到 |
| 异步事件流 | 「窗口里看见的」不等于「本次请求触发的」：判因果前先排空到静默（连续若干次读空），再发被测动作。实例：把启动后自发的事件当成首个请求触发，写进台账，排空实验才推翻它 |

**「连不上 / 不可达」只能记 `unknown`，除非同一条工具链有阳性对照。** `curl telnet://host:443` 不发 TLS 握手，对任何 TLS 端点都只是超时；给不出「同一个工具刚刚打通了别的目标」就别下环境结论，换协议匹配的探针（真客户端、真握手）再判。

**能操作不等于知道在哪。** 动鼠标/注内存之前先做状态判定：**优先读进程内状态字段 / 日志 / API，屏幕锚点只作最后兜底；固定延时不是状态判定**。判定不出来时显式返回 `unknown`。**驱动同理**：能调状态机 / 命令入口时，驱动走状态机 / 命令入口；输入自动化只用于证明输入通道与光标驱动的玩法路径。

**输入自动化**（GUI/拖拽）：合格输入仪器 = **状态回读 digest + 坐标标定图 + 分阶段驱动**；正例（按住已知 body 会动）与负例（错 y 轴/DPI、松开按键、错 body id）各一条。细节见 `references/instruments.md` §0.7。

**输入-owned 状态**：引擎每帧刷新的目标/按键/光标字段从外部写会与输入循环竞态；改走进程内 API/代理注入。状态机/菜单切换是异步的：等 0.5–1 s 并**复查 level + menu + 控制器已 arm** 再动作（I26）。

**oracle 可观测时先差分，后推断。** 有参考实现（原版二进制 / 旧服务 / 影子流量）能对同一输入给输出时，第一步把它的 I/O 抓下来（武器清单见 §6）。

**未知签名 / 布局先做最小探测。** 错误 ABI 不必然崩：cdecl 的多余参数由调用方清理、静默忽略，写坏的是对象头部，症状延迟到无关调用才出现。用「逐参数 / 逐字节置 1 + 最小可崩调用」定槽位，再拿反汇编确认；「跑通一次」不构成签名正确的证据（instruments §0.3）。

**静态算式只是候选。** 反编译给出路径、常量与运算符，乘除的对象/角色仍可能读反（常数与路径都相同）。写 claim 前用 oracle 的一次真实调用记下输入/输出，先定方向与幅度。

**批量 A/B / 驱动类仪器**：每 pass 复位环、计数器、live 状态与 scratch surface（返回「上一状态」的像素 / 对象 op 也要复位）；六件自证见 `references/instruments.md` §0.9。

**替换 / 桩**：命中计数 > 0、输入存在性自证、旁路同向（I36）；`s_calls=0` 的行不可用。

**参考录制的输入要与替换运行同源**：录制侧注入同一份计划输入（pin 生成器 + md5 + `--check`），并证明 pin 下参考可重现；判据命令显式带 pin（instruments §0.8）。

**完成判据**：至少一个预测被证伪（两个都灭 = 假设错，另起一行 `待证`）；输出能贴进台账的出处列。

### 2.3 Record

2.1 已预注册 `待证` 行；Probe 结束后**更新这一行**：状态改 `已证（行为）` / `已证（机制）` / `已证（现象）` / `已证伪`（限定见 §8），补可重放的出处（路径+行号 / 命令 / 观察步骤 / A/A 地板）。同一 claim 的重复探测不另起新行。

**完成判据**：出处能被另一个人照着重放出同一结论；引用探针时按 §2.2 的归宿写全路径与生成命令。

### 2.4 Promote

| 结论 | 动作 |
|---|---|
| 成立 | 折叠进正式代码 + plan 追加任务（`依据：F01`） |
| 不成立 | 台账划掉该行 + 原型回滚 |
| 仍不确定 | 记 `待证`，写明下一轮要区分的两个假设 |

任务行带 `依据：F01, F02`；依据缺失或指向不存在的 id → 拒绝开工（台账已漂移，先修台账）。原型存 `probe/<project>` 分支并在 plan 写 `原型：probe/<project>@<sha>`；仓库已有 gitignored 的 `work/` 时放那里。提交前缀跟仓库 `git log`，没有约定时用 `probe(<scope>):`。plan/todo 放仓库约定的计划位置（有约定就用它的；没有时用 `docs/plans/`）。升成仪器时 docstring 备齐四件事（命令 / 判据 / 覆盖边界 / 失效条件），见 `references/instruments.md` §0；提交前跑一次正例并把输出写进台账。

**判据命令必须可复现**：判据只指向 tracked 的永久仪器目录（如 `tools/`）；一次性脚本留在 gitignored 探测目录、不进判据。**输入语料可放 gitignored 目录**，但判据行要写来源与指纹：机器生成语料 = tracked 生成器 + md5 + `--check`（重生成逐字节一致）；人工 / 真实录制 = 录制命令 + oracle md5 + 事件流 md5，只作 L4 或回放基准；两者都缺 = 该行不可用。红先核对是否就是登记的那份语料，再到干净 HEAD 的 worktree 复跑，两者都红才按本批回归处理。

生成器的**输入**也要仓库可得（fixture 或 tracked 源）。唯一例外是**权威常量只存在于构建产物**里（编译器生成的 id 表、schema 展开）——这时从产物取，不要自己重算：重算等于第二实现，差值往往只落在少数条目上，手写语料全绿也查不出来（实例：源码行 crc32 与规范化 crc32 在 422/3464 个定义上不同，只有随机语料用数字形态才暴露）。例外必须同时满足三条：产物由本仓库构建、门禁里 build 排在 `--check` 之前、生成器 docstring 写明前置。验收仍是 `git archive` 导出到空目录后跑一遍全部门禁（先构建，再 `--check`）。

**改造路径优先选不失效已证证据的那条**：plan 里写的实现机制默认只是 L1 假设；动手前比较失效面——改共享布局 / 长度会作废既有语料与已证行（须同批改生成器与元数据），新增侧信道（文件输入 + 每 pass 播种 + 显式桥）保留证据。除非共享布局本身就是被测合同，默认后者，并在台账写明为什么没走 plan 原方案。

**完成判据**：四条归宿各有落点——台账行状态已更新、plan 有依据行、脚本已升仪器或已删、原型已定位（分支或 `work/`）。

## 3. 停止条件

只有三条，触发即停：

1. 下一步不可逆（删源资产、改存档/缓存格式、覆盖共享资源、改生产数据、改系统默认音频端点/混音器）→ 要批准。
2. 唯一依据是 L1 → 先补 L2+。
3. 已授权任务的依据被证伪 → 重评该任务及全部下游。

仪器不可用（地板无穷大、抓不到目标状态）时换仪器或换尺度，继续。

## 4. 证据等级

| 等级 | 来源 | 可授权 | 不可授权 |
|---|---|---|---|
| L1 | 反编译源码（dnSpy/ILSpy/jadx/apktool 产出） | 探测方向 | 实施、验收、spec 里的「事实」 |
| L2 | 字节码/指令、符号表、反射或类型 dump；自有解析器对目标数据的 dump；代理/转发层抓到的真实调用序列（实参+返回值） | 该符号或该数据集范围内的实施；范围 = 被观测的输入/关卡集合，换输入要新观测 | 跨模块行为推断；状态机/时序行为（调用序列不带时间与异步完成信息）；未观测输入上的泛化 |
| L3 | 日志、断点、profiler、单测断言 | 实施 + 技术验收 | 玩家/用户可见行为 |
| L4 | 实机观察；独立第二实现输出一致；同一条真实序列重放逐条一致 | 验收、写进 AGENTS.md、回归基准 | — |

**用户口述定级**：谈意图 / 范围 / 取舍 / 验收口径时，用户是权威（可进 plan / backlog / glossary 的命名决定）；谈被测物行为 / 格式 / 调用约定时，口述只算 L1 线索——记忆会错、文档会漂移，落 `已证` 要 L2+ 或探针判据。

**L2 只授权被观测范围**：行为、时序、输出等价另要 L3/L4 或仪器判据。**取最低可信来源**，不取最高。一条事实混了两种来源就拆成两行。L1 与 L4 冲突时以 L4 为准，并给 L1 那行加勘误。

## 5. 报结论

只有「有差异 / 无差异」的结论需要**四件套**；实施记录、覆盖快照、状态流转走 §8。四件套缺一不算结论。

覆盖类结论（「全绿」「通过 N/N」）先看**判据定义域表**：`measured` 项才是结论，`unmeasured` / `unknown` 是缺口。测试全绿不是覆盖声明；表的枚举与完备性检查见 `references/coverage-domain.md`。

**主分母饱和不等于完成**：函数 / 文件数到 100% 后，进度必须切到枚举的行为 lane cell（每个开关取值 / 分支一格）；奖励项单列、不改主百分比。cell 的 `measured` 需 test + fact，`unmeasured` 需 blocker + close；队列不是分母（`references/progress.md`）。

**无可观测差异的分支不算行为证据**：纯转发（如 `DefWindowProcW` 返回 0）、返回常量或状态不变的 case，坏实现与真实现无法区分；它们只算 control-flow coverage，不能升 `已证`。要升级必须加可观测 spy（hook / 参数记录 / 状态写）制造差异。

**oracle 像 bug 也照抄**：与直觉相反的分支（丢实体、少一字节、把匹配判给反直觉的对象）不许「顺手修正」——改它等于换 oracle。单独锁一条 cell，台账写明它是反直觉行为，别让下一个人当成缺陷去修。

**旁路判据要单独证灵敏度**：主输出在错误实现下仍可能相等、差异只落在旁路（overlay / 外部调用 / 计数器 / 日志）时，负例必须做一次**只改旁路**的变异（主状态不动），断言首个分歧字段就是该旁路；缺这一步 ⇒ 该维度记 `unmeasured`。

**表面与旁路的结论先认捕获路径**：客户端重绘 / 全窗口合成重绘 / 真实表面是三条语义不同的路，判据元素必须在**判据所用的那条**里可见；`PostMessage(WM_NCACTIVATE)` 不合成激活态（要真实 `SetForegroundWindow` 并逐次校验，被前台锁拒绝判**无效**）；两侧 live 环不等先比最终可见输出，别为环相等删 draw；beep / cursor / capture 两侧各记常驻 live 环，modal 期间经控制通道读，负例只改旁路。细则：`instruments.md` §0.9–0.10。

**随机语料不是「再多测一遍」**：判据只有一条——同 seed 的语料两侧逐字节相同；三条自检是语料指纹随 seed 稳定（每轮打印 `corpus md5`）、oracle 连跑两遍的 A/A 地板、每个入口的用例数 > 0。语料 = 按 schema 结构化生成 + 对既有语料做结构 / 字节变异；**会让被测物 abort 的形态先探明再排除**（abort 没有输出可比），排除项记 `unmeasured` 并写原因。零分歧只说明这批语料没找到差异，台账要写指纹与条数。**语料必须嵌真实时钟时**（如消息 id 要贴近 `now` 才能过校验），指纹按去掉时间戳的模板算，否则 `corpus md5` 每轮都变、指纹失去意义。

**终态相同 ≠ 过程相同**：两条路径可能落到同一终态（例：空文本 → 对话框重开 → 42，与「空文本被当成 42」）；只比终态时负例不检出。判据加**过程计数**（dialog_open 次数 / retry 次数 / 调用环条数），并让负例只改这个过程。

**取消路径也带隐藏推进**：取消常被当成「什么都不做」，但门之前可能已经取了随机数 / 推进了游标 / 增了计数；终态相同掩盖它。用 cancel → 同一动作再来一次的**第二次结果**做判据，让负例只改这个隐藏推进。

**reacher-only 检查点可以收口，但两半都要写**：UI 上不可达的分支标 `measured` 需要三件——① 真实路径对该参数的读取次数为 0（仪器计数）；② 函数面 A/B 覆盖该分支本身（引用 leaves / fact，含必失败负例）；③ fact 写明宿主没有这条路径、为什么不需要实现。缺一项保持 `unmeasured` + 回流条件（`claims.md`）。

**`已证` 只覆盖语料走到的分支**：callee 对齐不能替调用方担保未测分支——调用方进到该分支 ⇒ 调用方 `blocked`，callee 的 spec 列出未测分支与回流条件。

**消息用例 ≠ 分支 cell**：一条消息可能先命中提前门而根本没执行 dispatch 分支；转发 / 常量分支没有可观测差异，坏实现与真实现无法区分。按「消息 × 门控前置 × 入口」枚举 cell；转发 / 旁路 cell 加 spy 与必 FAIL 负例，否则只算 control-flow coverage，记 `unmeasured`（I47，`coverage-domain.md`）。

**`已证` 只锁「S 与该函数等价」，不担保宿主接线**：WndProc 消息表、菜单、光标、资源、CLI 是独立的宿主功能判据；缺判据视为不支持并进 backlog。宿主把已对齐函数的语义另写一份 = 第三个实现，必须自带 A/B，否则按 `partial` 记。容器级副作用（居中 / 尺寸 / 焦点 / owner）同属宿主接线，按调用点判据：在目标线程内读几何，用**公式期望值**逐侧比实际，绝不跨进程比绝对坐标（I39）。

**同一命令的多个入口要收敛**：WndProc case、控件菜单、加速键可能各写一份；只修一个入口 = 缺口仍在。抽成单一 helper 后，**每个入口各留一条 smoke**。跳表里多个 id fall through 到同一块时，按 id 列出块**前后**的调用序；A/B 覆盖了共享块 ≠ 覆盖每个 id 的调用点。

**S 的域外早退不是 oracle 的域外**：S 对某参数组合直接早退只说明实现没写；该组合记 `unmeasured` + backlog，并给下游留一条同组合的判据。

**A/B 差异先过仪器区间**：首个分歧落在 setup/prep（句柄、颜色表、注入视图、采集环 / 表容量）时不出结论——prep 摘要逐 pass 相等、环 / 表容量与溢出计数进判据（I32）。`integration` 不替代 canned A/B：函数升级只认替换 stub 后重跑同一 A/B（`references/claims.md` 台账粒度）。

**单侧劫持不是对称替换**：live-object hijack 只截获**经过该指针**的调用；S 若直接调用自己的 dispatcher，劫持对它无效。行为 lane 用 record-and-forward，router-only lane 用两侧同源的 canned 返回；先证两侧 ring 都命中（计数 > 0、首条 entry 存在），再解读分歧（I46，`instruments.md` §0.12）。

- **地板**：两次**独立采集**的差值 = ___（量化下限见 `references/instruments.md` I21）
- **边界**：仪器看不见 ___
- **判据形态**：个数 / 幅度 / 逐位 / 几何（bbox / 顶点 / 边方向）
- **尺度**：崩溃 / 调用序 / 状态数值 / 输出（每个数字带观测单位，I23）

- **A/A 要独立**：同一份日志或同一帧重放两次只证明解析确定；地板要两次独立采集（I24）。动画 / 悬停 / 物理运动会随时间变，先钉同一瞬时态（时刻、输入、状态字段），静态项与动态项分开报。
- **状态 / 计数 claim 的地板** = 两次独立启动同一脚本的同一量（如两次 `steps` 相等、同一对象集合）；启动抖动使计数不稳时，地板取集合或区间，不取单点。**状态序列的地板按驱动源拆**：脚本 dispatch 触发的切换，其绝对时刻含调度抖动；产品自身过渡的间隔是另一个量——两个数分开报，不把一个当另一个的精度。
- **尺度不外推**：存在性（集合 / 调用序）、数量（计数 / 幅度）、数值（逐位 / 容差）是同一件事的不同侧面——集合相等不说明逐位一致；固定 wall-clock 窗口的计数不可复现时判据取集合。三个尺度分开写。
- **输出层只覆盖最外层**：`corr=0.9999`、像素 `mean|Δ|` 证明的是混音/渲染后的重合；内部逐位另证。

几何层（I17）、输入自动化（I25）、物理 vs UI（I26）、A/B 实现级别（I27）、采集失败分桶（I28）、私有桌面像素与完成标记（I29/I30）：`references/instruments.md`。覆盖类的量化（A/A 对称差、并集、逐单元归因）：`references/claims.md`。

## 6. 三种归因武器

| 武器 | 前提 | 关键规则 |
|---|---|---|
| **差分 oracle** | 参考实现可运行、输入可完整记录 | 抓取层透明（代理占位，实参/返回值/指针内存全记，栈与寄存器不动）；只认**首个分歧**；输入记不全（时间戳/异步/线程调度）就改同脚本实机对拍 |
| **逐文件二分** | 两棵树都能独立构建 | 先对齐位移再比相似度（「同一位移」是要验证的假设）；每轮换一半文件重编重跑；`diff` 报的差异可能全无行为影响 |
| **修订夹逼** | 上游有修订史 | 算与重定位无关的逐函数相似度，找**跳变点**，不看单调漂移；全不跳 ⇒ 原版带本地补丁或来自别的分支；残差成簇 = 本地补丁，复原后判据是归零 + 一条负例 |

## 7. 偏离与回流

1. **边做边改是默认节奏。** 改动只许追加：plan 加一条变更记录（日期 / 依据 fact id / 受影响任务 / 新决定），已批准条目原样留着。
2. **依据被推翻** → 走停止条件 3：台账勘误 → plan 追加变更 → 重评下游 → 继续。
3. **中途或末尾追加需求** → 先发布到 `docs/agents/issue-tracker.md` 指定的 tracker（本地 markdown = `.scratch/<feature>/issues/`）；该文件不存在时写计划目录的 `backlog.md`。当前任务继续；只有与当前任务争用同一接口或同一份数据（做完要返工）才插入，并按第 1 条记变更。**暂缓 ≠ 取消**：每条写「为什么暂缓 + 回流条件」，需要人裁决的按 `docs/agents/triage-labels.md` 的 `ready-for-human` 标注；回流时先补 oracle 与二值判据再进队列。四类典型：

   | 类型 | 例子 | 回流条件 |
   |---|---|---|
   | 超出验收口径 | 逐位 PCM（合同只要求「差分」） | 口径改判，或用户明确要求逐位 |
   | 已被新链路取代 | 全量 oracle 采集（按需取样已覆盖） | 需要跨层同一时间线时 |
   | 路线冻结 | 旧实现路线留作对照物 | 新路线在某判据上覆盖不到 |
   | 不可判（无 oracle） | 1 ulp 残差 | 有了更细的量化下限或合成扫描 |

4. **需求不明确** → 先做一次会话内可运行、可展示的最小竖切，把它当探测：结论进台账，再写 plan。plan 跟随代码。
5. **新判据案件暴露既有缺口** → 当前窄 claim 先收口（fact 写明该调用点 `unmeasured`），另起台账行（open / blocked + 回流判据）；不要把缺口并进当前 fact，也不要顺手扩大实现。例：给某条宿主路径补用例时发现宿主实际走的是另一条入口，该路径另立 fact。
6. **残余任务按外部依赖分类**：agent 可做项耗尽时，剩余台账每行除「为什么暂缓 + 回流条件」外还要标外部依赖，否则「剩余 N 项」会把不可推进项混进可做项反复试跑。四类（`测平台` / `活动桌面` / `实时输入` / `目测`）的判据、默认处置与 `needs` tag 映射见 `references/progress.md`；属性非空的行不计入「agent 可做剩余」。

## 8. 台账

`docs/facts.md`（路径可用 `FACTS_FILE` 覆盖），**fact id 只增不减**（行内改状态、划删除线放行）。台账寿命永久，不混进计划文件（那里是周级的）。

| id | claim | 等级 | 出处 | 状态 | 影响 |
|---|---|---|---|---|---|
| F01 | 谱面时间戳是毫秒整数，不是秒 | L3 | `chart_parser.py` 实读 + 一条运行时日志 | 已证（行为） | T8 |
| F02 | ~~离线包不含音频~~ | L2 | `unpack.py` 不递归 | **已证伪** | T2 |

- 等级列只允许 `L1`–`L4`；细分用后缀（`L2-A` = 只覆盖 ABI 层）或复合（`L2/L4`）并在行内说明；未定级写 `待定`。
- 状态六种：`待证` / `已证` / `已证伪` / `已证（现象）` / `过期` / `快照`；`已证` 落盘写全 `已证（行为）` / `已证（机制）` / `已证（现象）`，不写裸 `已证`。上游变更（游戏更新、依赖升级、数据源换代）后把受影响模块的 L3/L4 行批量置 `过期`——结论会腐烂。
- **一行一 claim**：机制（为什么/能否）与覆盖（多少/哪些）拆行（`references/claims.md`）。
- `已证` 带限定：**`已证（行为）`** = 输出/调用序在 oracle 下对齐；**`已证（机制）`** = 还解释了**为什么**（反汇编/源码证据，或可复现的机制实验）。只有行为对齐时，claim 里写「机制未归因」——否则读者会把「已证」读成「知道原因」。**`已证（现象）`** = L4 实机观察到的差异（用户 / A-B 看到的现象），只授权记录与验收该现象；机制结论与修复另起 claim 补到 L2+。
- `快照` = 覆盖表 / 通过数一类**随构建变化**的测量：行内带构建指纹与四条自检钩子，规则见 `references/claims.md`；同一范围出新快照就把旧行置 `过期`。状态变化后重跑普查；写错的旧行标 `已证伪` + 删除线 + 勘误快照，不手改数字。
- **判据定义域表**是独立文档（默认 `docs/coverage-domain.md`），不混进台账；行状态 `measured` 时引 fact id，`unmeasured` / `unknown` 只占回流条件、不占 fact（`references/coverage-domain.md`）。
- 出处可重放：路径+行号 / 命令 / 观察步骤。
- 证伪：旧行划删除线并改状态，另起一行写勘误。行内改（状态流转、删除线）是唯一改法。
- **并发写**：id 取当前 `max+1` 并立即追加；并行会话可能同时追加（实测撞号）。撞号时只改**本轮新增**的行（重编号并在行内注明），不动别人的行；提交前查 `F\d+` 重复。**并行子代理不自行分配 fact id**：报告里用 `F2xx` 占位，编排者落账时统一分配并回告，避免同批撞号。
- **共享台账的部分暂存**：工作树里有别人未提交的行时，不要把整文件 `git add`。用 `git show HEAD:<facts>` + 只追加本轮新增行生成 blob，`git update-index --cacheinfo 100644,<blob>,<path>` 只把本轮行放进索引；`git diff --cached --numstat` 应等于本轮新增行数，工作树保留别人的改动。
- 追加落盘自证：新增 fact 用二进制或显式换行追加（文本模式读文件会把 CRLF/LF 静默转换）；写完看 `git diff --numstat`：只增行是 `N 0`；行内状态流转/划删除线是同数目的 `-/+`（如 `2 1`），这是唯一允许的删除，前提是 fact id 集合不变。成片对称删除或 id 丢失 = 整文件重写，回滚再提交。
- **改既有文件先看 diff stat**：一次 5 行编辑若报出成千上万行增删，几乎一定是文本模式写文件把 CRLF 改成了 LF（或反之）。提交前按 HEAD 的行尾约定归一化：`git show HEAD:<file>` 数 `\r\n`，用二进制重写该文件，再看 `git diff --stat` 是否回到本轮的几行。代码 / 工具文件同样适用；只对**本轮新增文件**自由选行尾。

- **自由文本字段含逗号必须加引号**：CSV 台账的 notes 里写 `{1,5,5}` 这类值会把行拆成多列，`git diff --numstat` 与 append-only 检查都看不出来；写完用 `csv.reader` 断言每行列数 == 表头，行尾先数 HEAD 的 CRLF/LF 再按同一约定写（文本模式会把整文件行尾换掉，diff 变成全文件）。

校验：在目标仓库根目录运行**本 skill 自带**的 `scripts/append-only-check.sh`（用法与退出码见脚本头部；默认检查索引，未暂存时退出 2，`--worktree` 检查工作树）。目标仓库没有该脚本时，至少跑 `git diff --numstat -- <facts> <plans>`（新增行 `N 0`；状态流转允许同数目 `-+`）和 fact-id 集合差（旧 id 全在、新增 id 无重复）。POSIX shell 里 `bash <skill>/scripts/append-only-check.sh`；`bash` 解析到 WSL 启动器时（Windows）改用 Git Bash 全路径。主干不留探测痕迹：`git log --oneline --grep '^probe' <主干分支>` 为空。
